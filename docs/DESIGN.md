# Шаблоны оформления сайта (Design system)

На сайте 6 вариантов оформления: **текущий дизайн (по умолчанию)** и **5 новых шаблонов**.
Шаблон можно назначить **всему сайту**, **отдельной странице** или **отдельному блоку** —
так из готовых частей собирается собственный дизайн.

Настройка: **Админ-панель → вкладка «Дизайн 🎨»**.
Сравнение всех шаблонов: страница **`design-preview.html`**.
Быстрый предпросмотр любой страницы: добавьте к адресу `?dsp=1…5` (например `stats.html?dsp=4`).

## Шаблоны

| № | Название | Характер |
|---|----------|----------|
| 0 | **Текущий · Классика Пестово** | Штатный вид сайта, по умолчанию. Ничего не переопределяется |

## Режимы

- **Единый шаблон** — весь сайт в одном оформлении.
- **Сборка из шаблонов (микс)** — у каждой страницы и у каждого блока свой шаблон.
  Значение «Текущий» = наследовать базовый шаблон.
  Кнопка «Применить выбранный шаблон ко всем страницам и блокам» раскладывает один шаблон по всем.

## Как это устроено

| Файл | Назначение |
|------|-----------|
| `css/design-presets.css` | Сами шаблоны: токены, правила блоков, точечные правила страниц, интерфейс вкладки |
| `js/design-system.js` | Реестр шаблонов/страниц/блоков, применение атрибутов, хранение выбора, образец разметки для предпросмотра |
| `js/design-admin.js` | Логика вкладки «Дизайн 🎨» в админке |
| `js/design-preview.js` | Страница сравнения `design-preview.html` (галерея, блоки, матрица отличий, конструктор) |
| `tools/test-design-system.js` | Проверки реестра и применения шаблонов (без браузера) |
| `tools/test-design-ui.js` | UI-проверки в jsdom: вкладка, предпросмотр, каскад сборки |
| `tools/test-design-save.js` | Регрессия: выбор реально сохраняется в базу и доходит до всех |

**Хранение.** Выбор лежит в Firebase `settings/design`:

```json
{
  "mode": "mix",
  "global": "1",
  "pages": { "stats": "4", "home": "5" },
  "blocks": { "card": "2", "nav": "3" },
  "updatedAt": 1767000000000
}
```

Дубликат в `localStorage` (`pestovo_design_settings`) — офлайн-резерв.
Listener в `js/utils.js` раздаёт настройки всем игрокам в реальном времени.
Если ключа в базе нет — работает текущий дизайн, ничего не переопределяется.

> **Важно для доступа к базе.** `db` и `currentUser` в `js/firebase-config.js`
> объявлены через `var`, а не `const`/`let`. Объявления `const`/`let` на верхнем
> уровне скрипта не создают свойство `window`, поэтому модули внутри IIFE
> (`js/design-admin.js` и другие), которые читают `window.db`, видели `undefined`,
> считали, что базы нет, и сохраняли выбор только в `localStorage`: у админа
> дизайн менялся, а до остальных пользователей не доходил. Не меняйте `var`
> на `const`/`let` в `js/firebase-config.js` — это ломает сохранение настроек
> для всех. Проверяется тестом `tools/test-design-save.js`.

**Атрибуты**, которые ставит `js/design-system.js`:

```html
<html data-dsp="4"            <!-- шаблон страницы: фон, типографика, точечные правила -->
      data-dsp-mode="mix"     <!-- single | mix -->
      data-dsp-page="stats"   <!-- какая страница открыта -->
      data-dspb-card="5"      <!-- итоговый шаблон блока «карточки» -->
      data-dspb-nav="3" ...>  <!-- …и остальных блоков -->
```

Итоговый шаблон блока вычисляет JS (личный шаблон блока, иначе — шаблон страницы/сайта),
поэтому у каждого блока всегда ровно одно подходящее правило CSS: сборка из разных шаблонов
не зависит ни от порядка правил в файле, ни от тонкостей каскада.

Предпросмотр в админке и на странице сравнения использует те же атрибуты на контейнере
`.dsp-scope`, поэтому показанный шаблон совпадает с боевым один в один.
