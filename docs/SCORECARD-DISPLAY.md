# Экранные счётные карточки

## Настройка

**Админ → Отображения счётных карточек**:

1. Выберите общий вид (1–5).
2. Для завершённых раундов оставьте **«Как общий вид»** либо выберите отдельный вид.
3. Проверьте предпросмотр: **1 / 2 / 4 игрока**, **9 / 18 лунок**, **активный / завершённый**. Изменение предпросмотра не публикует настройки.
4. Нажмите **«Применить для всех»**. Над вариантами показана сохранённая, а не черновая пара настроек.
5. **«Вернуть предыдущий»** восстанавливает предыдущую пару для всех пользователей. Это один шаг истории: после возврата можно вернуть отменённое оформление. Повторное сохранение тех же значений историю не стирает.

В завершённой карточке сразу показаны Gross, результат к пару и число сыгранных лунок каждого игрока. Детали раскрываются через **«Результаты по лункам»** (мышью, касанием или клавиатурой). В группе полное имя, ти и HCP находятся в шапке; внутри — номер и короткое имя, поэтому однофамильцы и одинаковые инициалы различимы. Приватность имён сохраняется: сокращается уже разрешённое для отображения имя.

Печать, PNG и настройки ввода счёта независимы от этих экранных видов.

## Хранение и совместимость

Атомарный документ Firebase Realtime Database:

```json
{
  "settings/scorecard_display": {
    "view": "2",
    "completedView": "inherit",
    "previous": { "view": "1", "completedView": "4" }
  }
}
```

- `view`: строки `1`–`5`.
- `completedView`: строки `1`–`5` или `inherit`.
- `previous`: предыдущая пара, без вложенной истории.
- Администратор сохраняет/возвращает пару транзакцией. `previous` берётся из фактических данных транзакции, а не локального кэша. Оптимистические события этой записи отключены (`applyLocally: false`).
- Пока документа нет, используется прежний `settings/scorecard_view`. При первом сохранении старое значение читается из базы и становится точкой возврата. Новая конфигурация после этого имеет приоритет.
- Права не расширялись: узел `settings` уже публично читается и записывается только администраторами.
- Экранные карточки помечены `data-sc-completed`. Изменения настройки обновляют только `data-sc-view`, не закрывая раскрытые детали и не изменяя счёт.
- История без явного статуса, но с `completedAt`, считается завершённой. Явный статус активного раунда имеет приоритет над старой датой.
- Кэш `pestovo_scorecard_display` обеспечивает последнее известное оформление при офлайн-загрузке; при восстановлении связи Firebase-подписка получает актуальные значения. Ошибка чтения не сбрасывает кэш.
- Вкладки одного устройства дополнительно синхронизируют кэш через событие `storage`.
- После установки этого релиза ранее открытая PWA должна загрузить новый код через существующий баннер обновления. Последующие изменения самих настроек не требуют перезагрузки.

## Проверки

```sh
npm test
npm run check:scorecards
npm run check:scorecard-pwa
npm run check:bundle
```

`tools/test-completed-scorecards.js` проверяет итоги, все варианты, предпросмотр, сохранение/возврат, миграцию, ошибки записи, наследование, обновление и повторное открытие карточек.

`tools/check-scorecard-mobile.js` проверяет 180 комбинаций (3 ширины × 5 видов × 3 состава × 2 длины × 2 состояния), отсутствие переполнения страницы, раскрытие клавиатурой и элементы админки.

`tools/check-scorecard-realtime-pwa.js` открывает независимые контексты администратора и игрока, запускает настоящие `js/pwa.js` и `sw.js` и проверяет обновление без перезагрузки, сохранение раскрытых деталей, повторное открытие, офлайн-перезагрузку, восстановление связи и возврат предыдущего вида. Firebase-транспорт заменён локальным HTTP/SSE-сервером с проверкой версии при записи; производственная база не используется. Это автоматизированная проверка Chromium с service worker, не тест физической установки приложения на iOS/Android. Проверка включена в browser CI.

В песочницах без системных NSS-библиотек можно использовать библиотеки из `@sparticuz/chromium/bin/al2023.tar.br` через `CHROMIUM_EXTRA_LIBS`. Для теста двух браузерных контекстов не используется `--single-process`.

После изменения `src/` выполните `npm run build`, затем `npm run assets` для обновления хешей ресурсов и precache PWA.
