# Формы имён при синхронизации гандикапов («Наташа» = «Наталья» = «Наталия»)

## Что было не так

Синхронизация гандикапов с базой АГР (`hcp.rusgolf.ru`) сравнивала имена как
обычный текст. Нормализация (`impNormName()`, `js/admin.js:2192`) приводила имя
к нижнему регистру и меняла `ё` → `е` — и всё. Поэтому:

| Место в коде | Что происходило |
|---|---|
| `rgNamesMatch()` (`js/admin.js:2728`) | «Наташа» ≠ «Наталья» → игрок попадал в **«не найдено»** |
| `rgBuildSearchQuery()` (`js/admin.js:3611`) | в АГР уходил один запрос «Смирнова Наташа» — в базе такого имени нет, ответ пустой |
| `rgGetFioKey()` (`js/admin.js:3412`) | «Смирнова Наташа» и «Смирнова Наталия Петровна» считались **разными игроками** → дубли с разными HCP |
| `impRenderPreview()` (импорт Excel) | строка «Наталия Смирнова» не находила игрока «Смирнова Наташа» → создавался второй игрок |

Дополнительно `rgGetFioKey()` включал в ключ отчество, поэтому даже одинаковые
имена с отчеством и без него не склеивались.

## Что добавлено

* **`js/name-variants.js`** — словарь форм русских имён (140 имён, см. таблицу
  ниже) и три режима сравнения. Работает и в браузере, и в Node (для тестов).
* **`js/admin.js`** — режим применяется в `rgNamesMatch()`, `rgGetFioKey()`,
  `rgFindDuplicateGroups()`, `rgBuildSearchQueries()`, `impNameKey()`.
* **Админка → вкладка «АГР» → блок «Формы имён»** — переключатель режима,
  поле своего словаря и кнопка «Проверить имена игроков».
* Настройки хранятся в `localStorage` и в Firebase (`settings/nameMatching`),
  то есть общий режим видят все администраторы.

## Три варианта — что выбрать

| | Вариант 1 · `A` Словарь | Вариант 2 · `B` Словарь + допуск | Вариант 3 · `C` Максимум |
|---|---|---|---|
| Формы имени из словаря | ✅ | ✅ | ✅ |
| Латиница (`Natalia` = Наталия) | ✅ | ✅ | ✅ |
| Род фамилии (Смирнов/Смирнова) | ❌ | ⚠️ только «на выбор» | ⚠️ только «на выбор» |
| Транслитерация фамилии (Smirnova) | ⚠️ только «на выбор» | ⚠️ только «на выбор» | ⚠️ только «на выбор» |
| Опечатки (Ноталья → Наталья) | ❌ | ⚠️ только «на выбор» | ⚠️ только «на выбор» |
| Инициалы («Н. Смирнова») | ❌ | ❌ | ⚠️ только «на выбор» |
| Основа фамилии (Смирн/Смирнова) | ❌ | ❌ | ⚠️ только «на выбор» |
| Свои формы (Лёля = Ольга) | ❌ | ❌ | ✅ |
| Запросов к АГР на игрока (макс.) | 3 | 4 | 5 |
| Риск перепутать однофамильцев | минимальный | низкий | средний |

**Как читать таблицу.** «⚠️ только на выбор» — совпадение не применяется само,
а попадает в блок **«Выберите нужного игрока»**, где админ нажимает «Это он» /
«Обновить этого» / «Добавить нового». Автоматически HCP обновляется только при
**точной фамилии** и **точной или словарной форме имени**.

Отдельный флажок **«Применять однозначные совпадения автоматически»**
(снять — и вообще ничего не обновится без подтверждения) даёт максимальную
осторожность в любом из вариантов.

Режим **«Не учитывать» (`off`)** оставляет прежнее поведение — на случай, если
что-то пойдёт не так.

### Настройки по умолчанию

Решено так: **из коробки ничего не меняется** — режим «Не учитывать» и
флажок «Применять совпадения по форме имени автоматически» снят.
Нужный вариант администратор включает сам: **вкладка «АГР» → «Формы имён» →
выбрать режим → «Сохранить»**. Настройка общая (Firebase `settings/nameMatching`),
так что включённый режим видят все администраторы.

Пока флажок автоприменения снят, совпадение по форме имени **ничего не меняет
само** — оно попадает в блок «Выберите нужного игрока». Точное совпадение имени
и фамилии обновляет HCP всегда: на него флажок не влияет, обычная синхронизация
работает как раньше.

* **Вариант 2 (`B`)** — оптимум: закрывает и «Наташа/Наталья», и опечатки, и
  «Смирнова/Смирнов», но всё спорное отдаёт на ручное подтверждение.
* **Вариант 1 (`A`)** — если нужен минимальный риск: только словарь, фамилия
  должна совпасть буква в букву.
* **Вариант 3 (`C`)** — если в базе много «мусорных» записей (инициалы,
  обрезанные фамилии, редкие домашние имена) и вы готовы чаще выбирать вручную.

## Что именно меняется при синхронизации

Для игрока «Смирнова Наташа» в режиме `B` в базу АГР уходят запросы по очереди
(следующий — только если предыдущий ничего не нашёл):

```
1. Смирнова Наташа      — как записано на сайте
2. Смирнова Наталья     — полное написание из словаря
3. Смирнова Наталия     — второе официальное написание
4. Наташа Смирнова      — обратный порядок слов
```

Ответ сравнивается с учётом форм имени, поэтому запись
«Смирнова Наталия Петровна, HI 18.4» находится и применяется.

## Проверка перед запуском

```bash
node tools/test-name-variants.js       # словарь и режимы off/A/B/C (79 проверок)
node tools/test-admin-name-sync.js     # реальные функции js/admin.js (27 проверок)
npm i jsdom                            # один раз, только для UI-теста
NODE_PATH=$(npm root -g 2>/dev/null || echo node_modules) node tools/test-admin-ui.js   # 18 проверок
```

Кнопка **«Проверить имена игроков»** в админке показывает по вашей реальной
базе: какие пары игроков система теперь считает одним человеком и какие формы
имени будут искаться в АГР.
