# Фоновые push-уведомления (PWA, приложение закрыто)

Клубные анонсы и вызовы судьи/маршала доставляются через стандартный
**Web Push (VAPID)** — работает на Android (Chrome/Edge/Яндекс) и на iOS
после «Поделиться → На экран „Домой“» и запуска установленной PWA.

## Как это устроено

1. Клиент (`js/pwa.js`) после разрешения «Уведомления» подписывает
   `pushManager` на публичный VAPID-ключ и сохраняет подписку в
   `/push_subscriptions/<key>` (endpoint, ключи p256dh/auth, uid, язык,
   признак админа).
2. Cloud Function триггерится при создании записей:
   - `/broadcasts/{id}` → `onBroadcastCreated` — анонс по аудитории
     (`all` — вошедшим игрокам; `all + includePwa` — всем, включая
     гостей; `roster`/`protocol` — только указанным uid);
   - `/alerts/{id}` → `onAlertCreated` — вызов судьи/маршала админам.
3. Функция (`functions/index.js`, библиотека `web-push`) шифрует payload
   и отправляет его в push-сервис браузера. `sw.js` показывает
   уведомление в обработчике `push`, `notificationclick` открывает нужную
   страницу.
4. VAPID-ключи генерируются автоматически при первом вызове функции
   `vapidSetup`: публичный — в `/settings/vapid_public_key` (читают все),
   приватный — в `/vapid/privateKey` (только сервер).

## Деплой (один раз)

Требуется план Firebase **Blaze**; веб-пуши практически бесплатны при
клубных объёмах.

```bash
npm i -g firebase-tools
firebase login
firebase use livescore-b77e4

cd functions
npm i
firebase deploy --only functions
```

После деплоя в админке: **Анонсы 📢 → «Фоновые пуши» → Создать/проверить
VAPID-ключи**. Кнопка вызовет `vapidSetup`, статус покажет количество
активных подписок устройств.

Если функции задеплоены в регион не `us-central1`, впишите полный URL
функции в поле на той же карточке — он сохранится в
`settings/push_function_url`.

## Правила базы данных (обязательно)

Приватный ключ не должен быть читаем из браузера. В Firebase RTDB Rules:

Минимально необходимое правило — закрыть приватный ключ:

```json
{
  "rules": {
    "vapid": { ".read": false, ".write": false }
  }
}
```

(остальные правила проекта остаются как есть; Cloud Functions работают
через Admin SDK и правила безопасности не применяются к ним). Клиенты
создающие подписки, должны иметь доступ на запись в
`/push_subscriptions/<ключ>` — в текущей открытой конфигурации клуба это
так и есть; при переходе на строгие правила разрешите авторизованным
пользователям запись собственной подписки.

## Диагностика

- На клиенте: `Notification.permission === 'granted'`,
  вкладка Application → Service Workers → Push (тестовая отправка в
  Chrome DevTools);
- подписка видна в базе `/push_subscriptions`;
- логи функции: `firebase functions:log -n onBroadcastCreated`;
- мёртвые подписки (404/410) функция удаляет автоматически.
