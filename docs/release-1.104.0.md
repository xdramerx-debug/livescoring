# Версия 1.104.0 — гости в автоподбор после раунда, варианты ввода счёта

Что вошло в релиз и как это проверить. Версия на сайте: футеры 13+ страниц и
`CACHE_NAME` в `sw.js` обновлены (`npm run assets` проверяет `?v=` и кэш).

## 1. Игрок, введённый при создании раунда, попадает в автоподбор после его завершения

**Было:** при старте группового/соло раунда игрок без профиля (только имя и
фамилия) записывался в справочник `usersPublic` сразу. Запись делал браузер
обычного игрока, а правила БД разрешали писать в `usersPublic/<uid>` только
владельцу профиля или админу. Гостевая запись `guest_…` отклонялась молча,
поэтому в быстром автоподборе такой игрок не появлялся.

**Стало:**

- При создании раунда гость только разрешается (поиск существующей записи по
  ФИО), **в базу не пишется** — флаг `deferWrite` в `resolveOrCreatePlayerUser`
  (`js/utils.js`), его передают `js/live.js` (группа) и `js/solo.js` (соло).
- При завершении раунда (`saveHistory`, `js/utils.js`) каждый гость раунда
  записывается в `usersPublic/guest_…`, даже если карточка без результатов.
  История по-прежнему пишется только при наличии счёта.
- Правила (`database.rules.json`): любой вошедший пользователь может **создать**
  запись `usersPublic/guest_…` с `isGuest: true` и обновлять такие же гостевые
  записи. Чужие профили и поля `role` / `admin` по-прежнему закрыты.

> **Важно:** изменение `database.rules.json` нужно выкатить в Firebase
> (`firebase deploy --only database`). Без деплоя правил запись гостя по-прежнему
> будет отклоняться. См. `docs/SECURITY-RULES.md`.

Проверка: создать группу из двух игроков, один с именем и фамилией без профиля;
завершить раунд; в «Игроки» и в выпадашке автоподбора при создании нового
раунда игрок должен появиться (на другом устройстве тоже).

## 2. Админка «Ввод счёта»: варианты вместо фиксированных пяти

Вкладка **«Ввод счёта ⛳»** теперь управляет списком вариантов:

- **Добавить / изменить / удалить** вариант. Удалить можно любой, кроме
  последнего; при удалении активного активным становится другой вариант.
- У каждого варианта свой **стиль** (1–5), **название**, **порядок блоков** и
  **«что показывать»**:
  - блок «Информация о лунке» целиком;
  - номер лунки, пар, дистанция (метры), дедлайн;
  - блок «Выбор лунки»;
  - фора (подписи «Фора +1» и метки ударов).
- **«Сохранить вариант»** — только записывает вариант, игроки его не видят.
- **«Сохранить и применить для всех»** / **«Применить для всех»** — записывает
  `settings/scoring_view`, `scoring_order`, `scoring_show`, `scoring_active`
  одной операцией; экраны игроков обновляются без перезагрузки.
- Предпросмотр показывает то же, что увидит игрок: скрытые элементы убираются
  по атрибуту `data-entry-hide` на `.score-entry`.

Хранение: `settings/scoring_variants/<id>` (список), `settings/scoring_active`
(id активного), плюс сводные `scoring_view / scoring_order / scoring_show` —
их читают экраны игроков (`js/utils.js`, `initScoreEntryLayouts`).

Изменённые файлы:

- `admin.html` — секция `#tab-scoreentry` (список, редактор, «что показывать»);
- `js/admin-display.js` — логика вариантов (`bindScoreEntryAdmin`,
  `saveScoreEntryVariant`, `activateScoreEntryVariant`, `deleteScoreEntryVariant`);
- `js/utils.js` — `normalizeScoreEntryShow`, `applyScoreEntryShow`, `data-entry-hide`;
- `css/style.css` — скрытие элементов и стили списка вариантов;
- `scorer.html`, `setup-round.html` — классы `h-hole` и `h-dl` у плиток.

Тесты: `tools/test-score-entry-variants.js` (11 проверок, jsdom),
`tools/check-score-entry-mobile.js` (браузер; обновлён под новую запись).

## Проверка релиза

```bash
npm install
npm run lint:syntax    # синтаксис
npm test               # все тесты, включая test-score-entry-variants
npm run assets         # ?v= в HTML + CACHE_NAME в sw.js
npm run check:bundle
firebase deploy --only database   # правила для гостевых записей (п. 1)
```
