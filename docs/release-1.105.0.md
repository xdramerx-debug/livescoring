# Версия 1.105.0 — история раундов гостей и игроков, добавленных позже

Что вошло в релиз и как это проверить. Версия на сайте: футеры страниц и
`CACHE_NAME` в `sw.js` обновлены (`npm run assets` проверяет `?v=` и кэш).

## 1. Раунды, завершённые игроком, добавленным позже, попадают в его профиль

**Было:** история раунда пишется клиентом того, кто завершил раунд
(`saveHistory`, `js/utils.js`). Клиент пишет `users/<id>/history` для каждого
игрока раунда и обновляет `roundsPlayed`, `bestGross`, `bestStableford`.
Правила (`database.rules.json`) разрешали писать в `users/$uid` только
владельцу или админу. Для гостя (`guest_…`), игрока, созданного вручную или
импортом, и для игрока другого аккаунта запись отклонялась молча. Флаг
`historyRecorded` при этом уже выставлялся, поэтому повторной попытки не было,
и раунд терялся для профиля.

**Стало:**

- `users/$uid/history/$hid`: писать может участник раунда (или его создатель),
  если цель записи — игрок этого раунда (`rounds/<roundId>/players/<$uid>`).
  Посторонний пользователь и `tournament-master` записать не могут.
- `users/$uid/roundsPlayed`, `bestGross`, `bestStableford`: записывать чужие
  агрегаты могут авторизованные клиенты только для гостевых записей
  (`guest_…`), значения проверяются на число.
- Игроки с аккаунтом: агрегаты чужих аккаунтов правилами не разрешены.
  Пересчёт (`pestovoDedupeUserHistory`) выполняется при просмотре профиля
  админом и выравнивает счётчики по истории.

> **Важно:** изменение `database.rules.json` нужно выкатить в Firebase
> (`firebase deploy --only database`). Без деплоя правил история не
> запишется, как и раньше. См. `docs/SECURITY-RULES.md`.

Проверка:

1. Создать групповой раунд с гостем (или игроком, добавленным через Excel или
   RUSGOLF, без аккаунта), завершить раунд с его карточкой.
2. Открыть профиль этого игрока в админке (вкладка «Игроки»): раунд должен
   появиться в истории и счётчике «Раундов».
3. На другом устройстве, где раунд завершал другой участник, профиль должен
   показать тот же раунд.

Тесты: `tools/test-history-rules.js` проверяет, что правила записи истории
сохранены в нужном виде.

## Проверка релиза

```bash
npm install
npm run lint:syntax    # синтаксис
npm test               # все тесты, включая test-history-rules
npm run assets         # ?v= в HTML + CACHE_NAME в sw.js
npm run check:bundle
firebase deploy --only database   # новые правила истории (п. 1)
```
