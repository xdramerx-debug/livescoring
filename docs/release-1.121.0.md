# Версия 1.121.0 — вызовы судьи и маршала снова доходят до телефона

Тестовое уведомление из админки показывалось, а настоящий вызов судьи или
маршала на телефон не приходил. Причин было две, обе — в цепочке
«браузер сохранил подписку → Cloud Function выбрала адресатов».

## 1. Подписка админа не получала флаг `isAdmin`

`js/pwa.js` (`pestovoPushPatchProfile`) считал админом только
`users/<uid>/role === 'admin'`. В клубе админ — это ещё и флаг
`users/<uid>/admin === true`; так же его понимают `hasAdminPanelAccess` в
админке, правила `database.rules.json` и серверная `wipeAllData`. У аккаунта
с флагом `admin: true` подписка оставалась без `isAdmin`, а
`onAlertCreated` рассылал вызовы только подпискам с этим флагом — список
получателей был пуст, в админке в статусе пушей стояло «админов: 0».

Что сделано:

- клиент теперь ставит `isAdmin` по любому из двух признаков и **явно
  сбрасывает** устаревший флаг у обычного игрока, а не только выставляет его;
- сервер перестал доверять флагу, который присылает браузер:
  `getAdminSubscriptions()` сверяет админов по профилям `users/<uid>` через
  Admin SDK (в обход правил) и принимает оба признака. Клиентский `isAdmin`
  остался запасным вариантом — для записей без `uid` и на случай, если
  профиль прочитать не удалось;
- сбой доставки в Telegram/VK больше не отменяет Web Push: раньше исключение
  внутри `deliverOfficialCall` уводило обработчик в общий `catch`, и телефон
  не получал ничего.

## 2. Обычный игрок не мог сохранить подписку вообще

`pestovoPushSave()` искал уже существующую подписку запросом
`/push_subscriptions?orderByChild=endpoint`. Читать эту ветку правила
разрешают только админам, поэтому у игрока запрос отклонялся с
`PERMISSION_DENIED`, промис падал, и запись **не создавалась**. То есть
фоновых пушей у игроков не было ни по анонсам, ни по вызовам — работал
только локальный тест в браузере админа.

Теперь отказ чтения — штатный путь: запись пишется напрямую под ключ
`sub_<хвост endpoint>`, который уникален для подписки и переживает повторную
подписку в том же браузере. Дедупликация по `endpoint` осталась для тех, кому
правила читать ветку позволяют (админам).

## Что проверить после деплоя

1. `firebase deploy --only functions` — правки в `functions/index.js`.
2. В админке: **Анонсы 📢 → «Фоновые пуши» → Обновить статус** — в строке
   «из них админов» должно быть больше нуля у того, кто открывал админку на
   телефоне с включёнными уведомлениями.
3. Сделать вызов судьи с лунки и закрыть приложение — уведомление должно
   прийти в течение нескольких секунд на телефон админа.
4. В логах функции (`firebase functions:log -n onAlertCreated`) появится
   строка `alert push: N admin subs of M`. Если N = 0 — у аккаунта, открывшего
   админку на телефоне, нет ни флага `admin: true`, ни роли `role: 'admin'`
   в `users/<uid>`.

## Проверки

- новый `tools/test-push-subscriptions.js` (16 проверок): подписка игрока
  сохраняется при запрете чтения ветки, ключ записи стабилен, `isAdmin`
  ставится по флагу и по роли, устаревший флаг снимается, дедупликация у
  админа не создаёт дубль. На коде 1.120.0 тест падает ровно на этих
  сценариях;
- `tools/test-functions-push.js`: `isAdminProfile` понимает оба признака,
  `getAdminSubscriptions` выбирает админов по профилям и не теряет запись с
  флагом без `uid`;
- `npm test` — весь набор зелёный, `npm run lint` — чисто.
