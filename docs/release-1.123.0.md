# Версия 1.123.0 — вызов судьи уходит в Telegram и ВКонтакте без Cloud Functions

В 1.122.0 доставка вызова судьи и маршала была починена, но работала **только
если задеплоены Cloud Functions**: сообщение отправляла функция
`onAlertCreated`, читая токены из ветки `channels/` через Admin SDK. Требование
заказчика на этот релиз — «мне не нужен cloud function, надо чтобы без этого
работало». Теперь вызов доставляет браузер того, кто нажал кнопку, а функции
остались необязательным усилением.

| | Кто отправляет Telegram/ВК | Cloud Functions | Токены видны |
|---|---|---|---|
| 1.122.0 | сервер (`onAlertCreated`) | обязательны, нужен тариф с Functions | только админу/мастеру |
| 1.123.0, режим `client` (по умолчанию) | браузер игрока | **не нужны** | любому вошедшему |
| 1.123.0, режим `server` | сервер (`onAlertCreated`) | нужны | только админу/мастеру |

Web Push в обоих режимах отправляет сервер, если функции задеплоены: браузер
игрока не может разбудить телефон судьи, когда страница свёрнута. Отсутствие
функций в режиме `client` отключает только push — Telegram и ВКонтакте
продолжают работать.

## 1. Доставка из браузера

Новая точка сборки — `pestovoDeliverOfficialCall()` в `js/official-alerts.js`
(и ESM-двойнике `src/official-alerts.js`, который уходит в бандл
`dist/livescoring-modules.js`). Обе прежние точки входа,
`sendTelegramOfficialAlert()` и `sendVKOfficialAlert()`, теперь делегируют
в неё, а не молчат.

Что она делает:

1. читает `channels/telegram` и `channels/vk` **один раз на страницу** и держит
   результат в памяти 5 минут (`pestovoOfficialChannels()`), плюс
   `settings/alert_delivery_mode`;
2. рассылает вызов в группу судей, в канал клуба (если настроен) и в беседу ВК;
3. пишет отчёт в `alerts/<id>/delivery` — тот же формат, что и серверный, но с
   `by: 'client'`, поэтому панель «Вызовы 🚨» показывает
   `📡 Доставка из браузера: Telegram (группа судей) ✅ · ВКонтакте ✅`.

Три вещи, без которых это работало бы неправильно:

- **Дедупликация.** `onSent` в `js/official-call.js` и `js/solo.js` зовёт обе
  точки входа подряд — раньше каждая отправляла своё. Теперь вторая получает
  тот же промис по ключу `alertId` (без него — тип + лунка + имя + 5-секундное
  окно) и ничего не шлёт. Судейский чат получает одно сообщение, а не два.
- **Статусы вместо тишины.** `sendTelegramSilentAlert()` и
  `vkSendMessageJsonp()` теперь возвращают `Promise<статус>`
  (`sent` / `not_configured` / `error: …`), а не `undefined`. Именно отсутствия
  обратной связи не хватало в 1.121.0: сообщение не ушло, а в интерфейсе —
  ничего. Игрок при этом по-прежнему не видит ошибок: тост остаётся
  «🚨 Судья вызван», а причина уходит в отчёт для админа.
- **Отчёт через `update()`, а не `set()`.** Сервер в любой момент пишет
  вложенный leaf `alerts/<id>/delivery/push` (число уведомлённых админов).
  Полная перезапись узла его бы стёрла.

## 2. Токены читаются вошедшим — осознанное ослабление

Браузер не может отправить сообщение, не прочитав токен. Поэтому
`channels/.read` изменён с «админ или мастер турниров» на `auth != null`:

```json
"channels": {
  ".read": "auth != null",
  ".write": "(root.child('users').child(auth.uid).child('admin').val() === true || root.child('users').child(auth.uid).child('role').val() === 'admin')"
}
```

Это откатывает находку 1 аудита `docs/CODE-AUDIT-2026-10-2.md` (P0: токен бота
в публичном `/settings`) лишь **частично**: интернет без авторизации токен
по-прежнему не видит, но видит любой вошедший, включая анонимную QR-сессию по
ссылке из раздевалки. Решение принято заказчиком явно; компенсации:

- **отдельный бот только для уведомлений**, добавленный только в группу судей:
  утечка такого токена даёт возможность писать в эту группу и читать её
  историю — и ничего больше. Бот не должен иметь доступа к другим чатам;
- **ключ сообщества ВК с правом «Сообщения»** (не «Фото», не «Стена», не
  полный доступ): то же самое — только переписка;
- токены **не пишутся в localStorage** (на общем планшете их прочитал бы
  следующий пользователь) и **не выводятся в консоль**;
- `.write` остаётся строго админским: подменить токен и увести вызовы в чужой
  чат игрок не может;
- переключатель режима (ниже) убирает токены из браузера целиком, если позиция
  по секретам изменится — код серверной доставки не удалён.

Предупреждение об этом показано админу в самой панели (**Вызовы 🚨**), а не
только в документации: решение должно быть видно тому, кто настраивает
интеграцию.

## 3. Переключатель режима доставки

`settings/alert_delivery_mode` — публичный узел без секретов:

- `client` (по умолчанию, узел может отсутствовать) — рассылает браузер;
- `server` — рассылает Cloud Function.

Админка → **Вызовы 🚨 → «Кто отправляет вызовы»**: селектор пишет настройку,
рядом — подпись выбранного режима (что нужно задеплоить) и предупреждение о
видимости токенов для браузерного режима. Правила допускают только эти два
значения (`.validate`).

**Дублей нет ни в одном из режимов**: браузер молчит при `server`
(возвращает `{ skipped: 'server_mode' }`), а `onAlertCreated` пропускает
рассылку по каналам при `client` и пишет в лог
`delivery mode = client, channels skipped`. Антиспам-ключ в функции при этом
не срабатывает и не мешает Web Push: в браузерном режиме ранний выход лишил бы
админов уведомления на телефон.

Кнопка «Проверить серверную доставку» сохранена, но её подсказка честно
говорит, что нужна она только в режиме `server`. Сообщение об отсутствующей
функции больше не пугает: в режиме `client` оно объясняет, что на работу клуба
это не влияет, и отправляет проверять кнопки «Проверить Группу / Канал / ВК».

## 4. CSP: ВКонтакте блокировался на проде

Браузерная отправка в ВК — это JSONP, то есть `<script src="https://api.vk.com/…">`.
В заголовке хостинга (`firebase.json`) `script-src` содержал только
`'self'`, `www.gstatic.com` и `cdnjs.cloudflare.com`, поэтому на проде такой
запрос блокировался бы политикой, а доставка молча не работала. Локально это
не воспроизводилось: dev-сервер vite таких заголовков не отдаёт.

Добавлено:

```
script-src 'self' https://www.gstatic.com https://cdnjs.cloudflare.com https://api.vk.com;
```

`connect-src 'self' https: wss:` уже разрешал `fetch` к `api.telegram.org`.
CSP при этом не ослаблен: ни `'unsafe-inline'`, ни `'unsafe-eval'`, ни `*`
в `script-src` не появились (проверяют `tools/test-inline-handlers.js` и
`tools/test-channels-secrets.js`).

## 5. Правила: кто имеет право записать отчёт

Отчёт о доставке в режиме `client` пишет браузер игрока, поэтому появился leaf
`alerts/$id/delivery/.write`:

```json
"delivery": {
  ".write": "auth != null && (root.child('users').child(auth.uid).child('admin').val() === true || root.child('users').child(auth.uid).child('role').val() === 'admin' || root.child('alerts').child($id).child('createdBy').val() === auth.uid || root.child('alerts').child($id).child('playerId').val() === auth.uid)"
}
```

Подузел отделён от `alerts/$id/.write` намеренно: само правило ветки —
«создать, но не трогать чужое», а отчёт — это изменение уже созданного вызова.

`createdBy` добавляет `requestOfficialCall()` (`js/utils.js`). Без него отчёт
не сохранился бы в самом частом сценарии: в QR-сессии `playerId` — это игрок,
а `auth.uid` — анонимная сессия устройства, и они не совпадают.

Запись best-effort: если правила не задеплоены, вызов всё равно уходит в
Telegram и ВК, а в панели админ появится подсказка
«Нет отчёта о доставке … выполните `firebase deploy --only database`» вместо
тишины.

## 6. Деплой

Обязательные шаги (Cloud Functions не нужны):

```bash
npm ci
npm run build            # бандл dist/livescoring-modules.js
npm run assets           # ?v= и CACHE_NAME service worker
firebase deploy --only hosting,database
```

`--only database` — **обязательный** шаг: без него браузер не сможет прочитать
`channels/` и вызовы не уйдут никуда. Правила меняются один раз.

Если функции уже задеплоены и хочется серверную доставку:

```bash
firebase deploy --only functions
```

и переключите режим в админке на «Сервер». Ничего не сломается и в обратную
сторону: оба отправителя смотрят на одну настройку.

Проверка без выхода на поле:

1. админка → **Вызовы 🚨** → режим «Браузер игрока»;
2. «Проверить Группу», «Проверить Канал», «Проверить отправку в ВК» — эти
   кнопки в браузерном режиме идут тем же кодом, что и настоящий вызов;
3. живой вызов во время раунда → в панели у вызова появляется строка
   `📡 Доставка из браузера: … ✅`.

## 8. Известные ограничения

- Браузер игрока обязан быть онлайн и с открытой страницей в момент нажатия
  (так и было: вызов создаётся оттуда же). Если вкладку закрыть между записью
  в `alerts/` и отправкой, сообщение не уйдёт — отчёт в панели это покажет;
- анонимная QR-сессия видит токен бота. Это плата за доставку без сервера
  (см. §2) — при неприемлемости включается режим `server`;
- `push_subscriptions` и Web Push по-прежнему требуют задеплоенных функций;
- браузерная отправка в ВК опирается на JSONP. Если VK когда-нибудь уберёт
  поддержку `callback=`, потребуется серверный режим.
