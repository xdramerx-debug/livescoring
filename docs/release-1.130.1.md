# Версия 1.130.1 — «Журнал гандикапов» и «Удалить все данные»

Патч-релиз: две кнопки админки, которые выглядели рабочими и не работали.
Причина у обеих одна по сути — модуль, который их обслуживает, не загружался
или не вызывался, а ошибка проглатывалась.

## 1. «Удалить все данные» (и соседние кнопки) ничего не делали

`js/admin-groups.js` (где живут `wipeEverything`, `clearAllData`,
`clearRounds`) и `js/admin-exports.js` (`downloadJSONBackup`,
`exportAllRoundsCSV`) подключены лениво — через
`<script type="text/plain" data-admin-lazy="…">`. Список групп для вкладок
находится в `js/admin-lazy.js`:

```js
data: ['display'],            // было
players: ['players', 'display'],
```

Вкладка «Управление данными» (группа «Система») грузила только
`js/admin-display.js`. Поэтому в момент клика `wipeEverything` был
`undefined`: делегированный обработчик писал в консоль
`[ui-events] нет обработчика: wipeEverything` и **молча выходил**. То же с
«Удалить все раунды», «Удалить всех игроков и раунды», «Экспорт CSV» и
«Бэкап базы» — пять кнопок, включая обе «опасные».

Исправлено в `js/admin-lazy.js`:

```js
players: ['players', 'display', 'groups'],
data: ['display', 'groups', 'importexport'],
```

Проверено в jsdom на настоящей странице `admin.html` с настоящим
`admin-lazy.js`: до правки `typeof wipeEverything === 'undefined'`, после —
функция загружается при открытии вкладки.

Дополнительно: если серверная функция `wipeAllData` не развёрнута, клиент
чистит базу сам, но часть веток (`scoreAudit`, `hcpLog`, `markers`) правилами
удалять нельзя — раньше в этом случае показывалось «нужны права
администратора», хотя права есть. Теперь сообщение говорит правду:
«Полное удаление делает серверная функция — разверните
`firebase deploy --only functions,database`».

## 2. «Журнал гандикапов» был пустым

Сама вкладка работала (рендер, поиск, история — это покрыто тестом), но
**главный способ поменять гандикап в админке не писал в журнал**: модалка
«Редактировать профиль» (`saveAdmPlayerEditor` в `js/admin-players.js`)
сохраняла `users/<id>/handicap` и не вызывала `pestovoLogHcpChange`.
Журнал заполнялся только из RUSGOLF-поиска при создании раунда, из
AGR-синхронизации, импорта Excel и добавления игрока-дубликата. Админ менял
гандикапы в профиле — и не видел в журнале ничего.

Теперь правка профиля пишет запись `manual-admin` со старым и новым
значением; сохранение без изменения гандикапа журнал не засоряет.

Ещё три правки в той же цепочке:

* `pestovoLogHcpChange` (`js/utils.js`) падал в ранний `return`, если
  `currentUser` ещё не заполнен (мастер-сессия, ранняя загрузка страницы).
  Теперь uid берётся и из `auth.currentUser`.
* `hcpLogLoad` (`js/admin-hcp-log.js`) при отсутствии индекса `.indexOn: ["at"]`
  (правила не развёрнуты) получал ошибку и показывал сырое
  `❌ Index not defined…`. Теперь есть фолбэк: читаем узел целиком и
  сортируем на клиенте — журнал видно даже без деплоя правил.
* Вкладка больше не молчит: «нет соединения с базой», «нет доступа»,
  «нет индекса» — разные сообщения с подсказкой, что именно сделать.
  Пустой журнал объясняет, чем он заполняется, а несовпадение поиска
  отделено от пустого журнала.

## Гейты

Новый `tools/test-admin-actions.js` — 15 проверок, две группы:

1. **Статическая: мёртвых кнопок в админке нет.** Для каждой из 18 вкладок
   `admin.html` каждый `data-act` должен иметь обработчик в файле, который
   эта вкладка реально загружает (напрямую или ленивой группой из
   `TAB_GROUPS`). Именно этой проверки не хватало: ошибка с пятью кнопками
   не видна ни в браузере (клик молчит), ни в консольных тестах.
2. **Поведенческая (jsdom):** правка гандикапа в профиле пишет
   `manual-admin` c `oldHcp`/`newHcp`; сохранение без изменения гандикапа
   записи не создаёт.

`tools/test-hcp-log.js`: 31 → **39 проверок**. Добавлены: фолбэк при
отсутствии индекса (читает узел целиком и всё равно рисует историю),
человеческое сообщение вместо `PERMISSION_DENIED`, сообщение об отсутствии
соединения, пустой журнал с подсказкой, отдельный текст для пустого
результата поиска.

## Что нужно сделать после выкладки

Правки клиентские, но журнал целиком оживает только с развёрнутыми
правилами и функцией:

```
firebase deploy --only database,hosting --project livescore-b77e4
firebase deploy --only functions --project livescore-b77e4   # wipeAllData
```

Без первого запись в `hcpLog` получит `PERMISSION_DENIED` (обновление
гандикапа при этом работает, в консоли будет `[hcp log]`), без второго
«Удалить все данные» почистит не всё и честно об этом скажет.
