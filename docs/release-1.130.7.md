# Версия 1.130.7 — карточку завершает любой участник, табло читает окно, зум на телефоне закрыт

Патч-релиз по трём жалобам с поля. Все три — про «страница делает больше,
чем показывает»: права на финиш были уже́ роли создателя, табло качало всю
историю клуба, а масштаб страницы менялся от случайного второго пальца.

## 1. «Завершить карточку» доступно любому участнику

**Что было.** Завершение раунда — один мультипуть в `rounds/$rid`:
`finishedPlayers/<uid>` + `completedBy` + `completedByName` + `status`.
Правило базы на сам раунд разрешало запись только создателю
(`createdBy === auth.uid`), админу и мастеру. Участник, который не создавал
раунд, получал отказ и видел тост «⚠️ Не удалось завершить раунд: …
Счёт сохранён — обратитесь к судье/комитету». Причём счёт при этом
сохранялся, поэтому ошибка выглядела необъяснимой.

**Что сделано.**

| Уровень | Правка |
|---|---|
| `database.rules.json` | `rounds/$rid/finishedPlayers/$pid` — собственное правило: игрок раунда пишет **за себя** (`auth.uid == $pid` и карточка `players/$pid` существует), независимо от того, кто создал раунд |
| `database.rules.json` | `status`/`completedAt`/`completedBy`/`completedByName`/`historyRecorded` — отдельные правила участнику, но **только когда** `finishedPlayers` покрывает всех игроков раунда; `status` принимает единственное значение `completed`, `completedBy` — только собственный uid |
| `database.rules.json` | `partialFinish`, `forcedFinish`, `forcedReason`, `autoCompleted=false` — досрочное и частичное завершение доступно участнику; `autoCompleted=true` остаётся за сервером |
| `js/live.js` | `doFinishGroupRound`: сначала своя карточка, затем (если сдали все) статус раунда — две отдельные записи |
| `functions/score-audit.js` | новая операция `roundFinishCard`: атомарно ставит отметку и закрывает раунд; единственный путь для гостевых карточек `guest_*` |
| `js/live.js` | клиент зовёт `roundFinishCard`, а прямым двухшаговым путём пользуется только при недоступности функций; отказ по правам не маскируется второй попыткой |

**Почему два шага.** Правило проверяет «сдали все» по **уже сохранённому**
состоянию базы. В одном `update()` участник, закрывающий карточку последним,
получал бы отказ именно на `status` (его собственной отметки в базе ещё нет) —
и снова не смог бы завершить карточку. Поэтому запись своя → чтение → статус.

**Корневой грант не ослаблен.** В RTDB дочерние правила только добавляют
разрешения: создатель, админ и мастер по-прежнему распоряжаются раундом
целиком, включая принудительный финиш (`roundForceFinishPlayer`/`All`),
автозакрытие (`sweepStaleRounds`) и финализацию турнира. Гость по QR не
совпадает с `auth.uid`, поэтому для него работает серверная операция —
по тому же контракту, что и ввод счёта (`scoreWrite`): свой аккаунт либо
доступ по карточке QR. Подробнее — `docs/SECURITY-RULES.md`.

## 2. Ограничение чтения раундов, а не только отрисовки

**Что было.** «Все раунды» подписывались на `db.ref('rounds')` целиком,
а пагинация резала уже загруженный массив (первые 50 строк + «Показать ещё»).
Замер из `docs/CODE-AUDIT-2026-10-2.md`: 300 раундов → 26 638 DOM-узлов,
191 мс на первый рендер и 105 мс на **каждое** обновление `/rounds`, то есть
на каждое сохранение лунки любым игроком у каждого открытого табло.

**Что сделано (`js/leaderboard.js`).**

- окно последних **100** раундов: `orderByChild('createdAt').limitToLast(100)`
  (индекс `.indexOn["createdAt"]` уже объявлен в правилах — правка правил
  не потребовалась);
- отдельная выборка активных раундов `orderByChild('status').equalTo('active')`
  — живое табло не теряет идущую игру, даже если она старше окна;
- `?round=<id>` вне окна дочитывается **точечно** (`rounds/<id>`), без чтения
  ветки; до ответа список не мигает «Нет раундов»;
- «Показать ещё» листает окно отрисовки, а когда оно исчерпано — расширяет
  окно чтения (+100) и переподписывается (старая подписка снимается);
- сводка периода честно пишет «· загружены последние 100» вместо того, чтобы
  выдавать окно за всю базу;
- заглушки Firebase в тестах не умеют `orderByChild`/`limitToLast` — на этот
  случай остался прежний путь через `bindRealtimeValue`, поэтому vm/jsdom-тесты
  работают без изменений.

## 3. Масштаб страницы на телефоне заблокирован

Ввод счёта идёт большим пальцем, стоя на поле: случайный пинч или двойной тап
увеличивал страницу, и карточка лунки уезжала за экран.

| Уровень | Правка | Платформа |
|---|---|---|
| `<meta name="viewport">` | `maximum-scale=1.0, user-scalable=no` во всех 15 страницах | Chrome/Android |
| `css/style.css` | `html { touch-action: manipulation }` — снимает зум по двойному тапу, прокрутка остаётся | все |
| `js/ui-events.js` | гашение `gesturestart`/`gesturechange`/`gestureend` | iOS Safari (с iOS 10 игнорирует `user-scalable=no`) |

Одиночные тапы и прокрутка не перехватываются: слушателей на
`touchstart/touchmove/touchend` нет, `preventDefault` вызывается только у
отменяемых событий масштабирования. Десктоп не затрагивается — эти события
на мыши не приходят.

> **Оговорка про доступность.** `user-scalable=no` отключает и полезное
> увеличение для слабовидящих. Это осознанное решение по запросу клуба для
> полевых страниц; если понадобится вернуть зум — достаточно убрать два
> атрибута из viewport и `touch-action` у `html` (JS-часть гасит только
> пинч-жест Safari).

## Деплой

1. Код: `firebase deploy --only hosting,functions --project livescore-b77e4`
   (`roundFinishCard` живёт в `functions/score-audit.js`).
2. Правила: `firebase deploy --only database --project livescore-b77e4`.

Порядок важен: если развернуть правила раньше функций, гостевые карточки
(`guest_*`) не смогут завершиться — правило требует `auth.uid == $pid`.
Личные аккаунты работают в любом порядке.
