# Версия 1.142.0 — точные размеры грина и схема лунки картинкой

К пин-позиции добавились две вещи, которые просят на поле: **числа** и
**картинка**. Раньше администратор выбирал зону 3×3 («дальняя левая»), и этого
хватало, чтобы понять сторону, но не расстояние. Теперь он вводит те же метры,
что показывает приложение для измерения грина, а игрок видит флажок в точке,
посчитанной по этим числам, — в том числе поверх настоящей схемы грина.

## 1. UP / SIDE / DEPTH в метрах

| Поле | Что значит | Пример |
|---|---|---|
| `UP` | Сколько метров **вперёд** от переднего края грина | `8,5` |
| `SIDE` | Сколько метров **в сторону** от центральной линии: `+` вправо, `−` влево | `-3,5` |
| `DEPTH` | Глубина грина от переднего края до заднего | `31,0` |
| `WIDTH` | Ширина грина (нужна, чтобы перевести `SIDE` в положение на схеме) | `26,0` |

Точка флажка считается так: доля вглубь = `UP / DEPTH`, доля в сторону =
`0.5 + SIDE / WIDTH`. Запятая и точка в поле равнозначны, `inputmode="decimal"`
открывает на телефоне числовую клавиатуру.

Почему `WIDTH` отдельным полем, а не «± от центра»: половина грина слева от
центральной линии не равна половине справа, и без ширины `SIDE` нельзя честно
перевести в картинку. Без `WIDTH` панель показывает глубину, а сторону — по
центру и честно об этом пишет.

Проверки ввода: `UP` не может быть больше `DEPTH` (флажок не стоит за задним
краем) — такая пара чисел считается опечаткой и отбрасывается при чтении, а
панель не ломается. Диапазоны: `DEPTH` 1–120 м, `UP` 0–120 м, `SIDE` ±60 м,
`WIDTH` 0–120 м.

Если чисел нет — работает прежняя зона 3×3, то есть старые данные и старый
редактор продолжают работать без миграции.

## 2. Схема грина картинкой

Админ загружает изображение лунки (скриншот из приложения измерения, фото
схемы, карта грина из планшета клуба), и панель игрока рисует флажок **поверх
этой картинки** по тем же числам.

- Передний край — **снизу** картинки: так схема совпадает с видом «с ти на
  грин», и `UP` растёт вверх по изображению.
- Картинка сжимается в браузере (`canvas` → JPEG, длинная сторона ≤ 900 px,
  качество 0.82 → 0.62 при необходимости) и лежит прямо в
  `settings/pin_positions` как `data:image/jpeg;base64,…`. Отдельного Firebase
  Storage в проекте нет, новая ветка правил и новый биллинг не нужны, а размер
  предсказуем: 60–120 КБ на лунку.
- Принимаются только `data:image/(png|jpeg|webp)` и `https:`-ссылки. Всё
  остальное (в том числе `http:` и `javascript:`) отбрасывается при чтении —
  схема приходит из базы и должна быть безопасной по умолчанию.
- Пропорции контейнера — это пропорции самой картинки (`height:auto`,
  `object-fit:contain`), иначе `cover` обрезал бы края и флажок разъехался бы
  с тем, что нарисовано.
- Без картинки остаётся прежний схематичный эллипс с сеткой 3×3.

## Что видит игрок

Под схемой — строка словами («Флажок 8.5 м от переднего края, ближняя часть,
левее центральной линии») и четыре числа с единицами (`UP 8.5 м`, `SIDE −3.5 м`,
`DEPTH 31.0 м`, `WIDTH 26.0 м`). Слова важнее чисел: на поле игрок читает
«сколько вперёд и куда», а не таблицу координат.

## Хранение

```
settings/pin_positions/holes/7 = {
  zone: "mc",                                     // запасной вариант 3×3
  note: "Флажок за бункером справа",
  measure: { up: 8.5, side: -3.5, depth: 31, width: 26 },
  image: "data:image/jpeg;base64,…"               // ≤ 900 px, ≤ 900 КБ в base64
}
```

Правила базы менять не пришлось: ветка `settings` уже открыта на чтение всем и
на запись администратору.

## Ограничения

- Схема хранится в реальном времени вместе с остальными настройками, поэтому
  подписка `/settings` выросла на размер схем: 18 лунок × ~100 КБ ≈ 1.8 МБ в
  худшем случае. Для клуба это приемлемо (одна загрузка на устройство), но
  если схем станет много — их стоит вынести в Firebase Storage и хранить в
  записи только URL (`normalizePinGreenImage` уже принимает `https:`).
- Загруженная картинка — это плоскость: панель не знает реальных пропорций
  грина на фото, поэтому ожидает, что схема нарисована «вид с ти», с передним
  краем внизу.
- Числа вводятся вручную; автоматического импорта из приложения измерения нет.
