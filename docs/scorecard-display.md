# Экранные счётные карточки

Админка → **Отображения счётных карточек**. Пять кнопок меняют только
предпросмотр шириной до 390 px. **Применить для всех** сохраняет выбор в
`settings/scorecard_view` (существующий ключ, значения `1`–`5`). Сообщение об
успехе появляется после подтверждения Firebase. Права записи не менялись.

1. Бланк клуба — девять лунок в одной таблице.
2. Блоки по 3 лунки — без горизонтальной прокрутки, крупнее.
3. Крупная лента — крупные клетки с прокруткой внутри карточки.
4. Вертикальный список — одна лунка на строку.
5. Плитки — крупный счёт, пар под ним.

Общий рендерер `renderClubScorecard` в `js/utils.js` используется главной,
лидербордом раундов, групповой/одиночной игрой, профилем/историей,
турнирными карточками, отдельными страницами игрока и маркера.
Одиночный игрок — личная карточка; группа (2+ игрока) — ОДНА общая карточка
на весь флайт (`renderUnifiedGroupScorecardHTML`): столбцы — игроки
(имя, ТИ, фора), строки — лунки в порядке игры, в ячейках — удары каждого.
Административные формы редактирования счёта не заменяются.

В карточке: выбранные ти рядом с именем, HCP, лунка, пар, счёт, промежуточные и общие итоги ударов.
SI, Stbl и отдельная строка «Фора» не выводятся. В карточках фора показана наклонными
черточками внутри квадрата счёта справа сверху с доступной подписью. На экранах ввода:
на крупном квадрате — подпись «Фора +1» / «Handicap +1» с иконкой мяча (красный при минусовой форе; это удары гандикапа, не штраф);
в мелких клетках сетки лунок форы нет (бейдж закрыл бы цифру) — там счёт игрока
и точка маркера в углу квадрата (мигает красным при расхождении) вместо подписи «М —».
Сохранены подсветка расхождения и текущей лунки. Незаполненный
счёт — тире; нулевая фора не наследует фору раунда.
Порядок и диапазон лунок берутся из раунда, в том числе старт с 10-й.

Подписка в общем `utils.js` обновляет уже открытые карточки без перезагрузки.
Для новых карточек используется текущее значение; localStorage хранит кэш.
Старые отдельные элементы выбора карточек групп и турниров убраны из админки.
Печать (`generateExactPestovoPaperScorecardHTML`), социальный PNG и справочное
«Поле клуба» с расстояниями не меняются. Печатные карточки админки (вкладка
«Счетные карточки» менеджера турниров и `TnMgrCore.scorecardsHtml`) показывают
фору так же — наклонными черточками в правом верхнем углу клетки счёта.
Черточки рисуются всегда, когда у игрока есть фора: если удары по лункам не
выбраны, они считаются от игрового гандикапа и индекса сложности лунки, а
скрытая строка «Фора» (панель «Состав информации» конструктора печати) убирает
только саму строку, не черточки в клетках счёта.

Проверки:

- `npm run test:ci` — включая общую карточку, адаптер турниров, девятки,
  нулевую/минусовую фору, разные ти и экранирование имени.
- `npm run check:scorecards` — Chromium, 320/390/430 px, все пять вариантов,
  отсутствие прокрутки страницы, предпросмотр без записи, общий выбор,
  обновление открытой карточки и отказ сохранения. База подменена заглушкой,
  запросов к production нет. Нужны установленные npm-зависимости и библиотеки
  Chromium; в минимальной песочнице можно использовать `tools/build-stub-libs.sh`
  и `CHROMIUM_EXTRA_LIBS=$PWD/tools/.browser-stub` (только для офлайн-тестов).
- После изменения статики: `npm run assets`.


## Экран ввода счёта — единый адаптивный дизайн

Админка → **«Ввод счёта ⛳»** (`#tab-scoreentry`). Старые пять числовых
вариантов и пользовательские копии шаблонов удалены. Экран использует один
адаптивный дизайн с контрастной информацией о лунке, крупной touch-навигацией,
панелями счёта и кнопками размером не менее 44 px на телефоне.

Вкладка позволяет глобально для всех игроков:

- включать и выключать элементы (информацию о лунке и её поля, навигацию,
  сравнение с маркером, карточку, судью/маршала, темп, QR, завершение раунда,
  Stableford, тайминг и уведомления);
- менять порядок основных блоков: информация → лунки → ввод счёта;
- немедленно применять изменения на уже открытых экранах.

Ввод и сохранение счёта и панель «Мой счёт» обязательны и не скрываются.
Глобальные настройки записываются одним объектом в
`settings/scoring_display`; localStorage используется только как офлайн-кэш.
Для группы, одиночного режима и отдельного `scorer.html` действует одна
настройка. Динамические заголовки показывают «Мой счёт: Имя Фамилия» и
«Счёт игрока: Имя Фамилия» без скобок.

Админка → **«Турнирный ввод счёта»** (`#tab-tncards`) полностью заменяет старые
варианты карточки и блоков. В ней настраиваются те же элементы и порядок для
всех турнирных QR-экранов; объект хранится в
`settings/tournament_scoring_display`. Если переопределение не задано,
турнирные раунды наследуют `settings/scoring_display`. Кнопка сброса удаляет
переопределение, а не копирует и не создаёт новый пресет.

## Счётные карточки на экране ввода результата (setup-round.html)

Админка → **«Карточки на вводе 🃏»** (`#tab-entrycards`). Меняет только две
карточки, которые игрок видит при вводе результата на `setup-round.html`:

- **«Общая карточка»** — группа из двух и более игроков (`general`);
- **«Счётная карточка по лункам»** — один игрок: соло-раунд и турнирный QR (`hole`).

Для каждой карточки доступны **5 видов**, три размера (`s` / `m` / `l`) и
переключатели элементов (формат, ти, HCP, пар, удары форы, маркер, текущая
лунка, подытоги по 9, итоги, счёт к пару, сыграно N/M, статус «на лунке»,
подсветка расхождения, подсказка). Для турнирного ввода можно задать свой вид
каждой карточки; «Как в обычном раунде» (null) наследует вид обычного раунда.

Виды общей карточки: 1 «Таблица клуба», 2 «Блоки по 9», 3 «Строки игроков»,
4 «Карточки игроков», 5 «Плитки лунок». Виды счётной карточки: 1 «Бланк клуба»,
2 «Тройки», 3 «Лента», 4 «Список», 5 «Плитки».

Превью в админке строится из демо-данных и черновика и **ничего не пишет в
базу**. Запись — кнопкой «Применить для всех» в `settings/entry_scorecard_display`
(одним объектом). localStorage (`pestovo_entry_scorecard_display`) — офлайн-кэш.
Открытые экраны перерисовываются сразу через `bindRealtimeValue`.
Несохранённые правки админа не затираются входящими настройками; «Отменить
правки» возвращает к актуальным сохранённым значениям.

Код: `js/entry-scorecard.js` (рендер, настройки, `pestovoEntryRoundCardHTML`),
`js/admin-entry-scorecard.js` (вкладка), `css/entry-scorecard.css` (стили,
темизация через переменные темы, включая светлый режим). Точки вызова —
единый экран раунда (`renderPlaySummary` и `renderGVPlayers` в `js/live.js`):
он обслуживает и одиночный, и групповой раунд (v1.126.0), отдельного
одиночного вызова `renderMiniCard` больше нет. Остальные страницы (главная, лидерборды, история, печать,
`scorer.html`, `marker.html`) этими настройками **не** управляются: они по-прежнему
используют `renderClubScorecard` / `generateGroupHoleTableHTML` из `js/utils.js`
и вкладку «Отображения счётных карточек».

Проверки: `node tools/test-entry-scorecard.js` (логика и разметка),
`npm run check:entry-scorecards` (браузер, 320/390/430 px; нужны заглушки
библиотек: `bash tools/build-stub-libs.sh` и `CHROMIUM_EXTRA_LIBS=$PWD/tools/.browser-stub`).

## Страница турниров — гибкая глобальная компоновка

Админка → **«Турниры: вид»** (`#tab-tournamentsview`). Вместо старых пяти
числовых пресетов доступны три адаптивные компоновки: **карточки клуба**
(дефолт), **лента стартов** и **компактный обзор**. В той же вкладке
администратор настраивает видимость элементов и порядок разделов «Активный
турнир → Предстоящие старты → Архив».

Настройки применяются всем посетителям страницы `tournaments.html` и
записываются одним объектом в `settings/tournaments_display`. Управляются
заголовок/поиск/разделы каталога, баннер, метаданные, форматы и описания
карточек, а также шапка, метрики, описание и вкладки страницы турнира.
Обновлённые карточки и детали также получают параметры после каждого
перерендера; localStorage является только офлайн-кэшем.

Проверки:

- `npm run test:ci` — нормализация глобальных параметров, их применение,
  realtime/совместимость, сохранение и сброс турнирных переопределений.
- `npm run check:admin-display-mobile` — все админские переключатели, стрелки
  порядка и кнопки на ширине 320–768 px; касания не меньше 44 px.
- `npm run check:display-mobile` — мобильные проверки настройки, каталога,
  деталей, лидерборда, группового и одиночного ввода.
- `npm run check:scorecards` — рендер счётных карточек и экранов ввода.
  В минимальной песочнице для Chromium используйте
  `CHROMIUM_EXTRA_LIBS=$PWD/tools/.browser-stub`.
- После изменения статики: `npm run assets`.
