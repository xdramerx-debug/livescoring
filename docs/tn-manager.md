# Менеджер турниров (вкладка «Турниры 🏆»)

Полный цикл работы организатора с турниром прямо в админ-панели: создание
турнира, раунды, группы, участники, стартовый лист с QR-кодами, счёт по
лункам, результаты и карточка игрока. Система переиспользует существующую
инфраструктуру клуба — публичный каталог `tournaments.html`, страницы
ввода счёта (`setup-round.html` / `scorer.html`) и общие правила Firebase.

```
admin.html → вкладка «Турниры 🏆» (#tab-tnmanager → #tnm-root)
  js/tn-mgr.js        точка входа TnMgr (open/boot, права доступа)
  js/tn-mgr-ui.js     маршрутизация, список, форма, карточка, модалки
  js/tn-mgr-sheet.js  вкладка «Стартовый лист»: генерация, QR, колонки, PDF
  js/tn-mgr-round.js  экран раунда (Счёт/Результаты) и карточка игрока
  js/tn-mgr-data.js   слой данных Firebase RTDB
  js/tn-mgr-io.js     печать PDF (окно печати), Excel (SheetJS/CSV), импорт
  js/tn-mgr-core.js   чистое ядро: форматы, поиск RU/EN, WHS, лист, результаты
```

## 1. Как пользоваться

1. **Турниры** — таблица «Название / Дата», кнопка «Создать турнир».
2. **Новый турнир** — название\*, дата начала\*, время старта\*, формат
   (мультивыбор из пополняемого справочника: 20 встроенных форматов + свои),
   клуб, поле, примечание. Кнопки «Добавить» / «Назад». Черновик формы
   автоматически сохраняется в `tnDrafts/<uid>` и в localStorage
   (`pestovo_tn_mgr_draft`).
3. **Карточка турнира** — «Назад», название + дата, «Изменить» и вкладки:
   - **Раунды** — «Добавить», таблица с датой (правится на месте), «Удалить»,
     клик по строке открывает экран счёта.
   - **Группы** — «Добавить группу», таблица «Название / HCP», «Удалить»;
     форма группы: название\*, гандикап от/до, пол, ТИ, формат.
   - **Участники** («Гольфисты») — поиск с автодополнением по фамилии на
     русском и английском, ручное добавление, импорт Excel/CSV, вставка
     таблицы, справочник игроков клуба, счётчики «Всего / мужчин / женщин»,
     удаление, экспорт в PDF.
   - **Стартовый лист** — генерация из участников, групп, ТИ, формата и
     раундов; инлайн-правка любого поля; колонки настраиваются; QR-коды
     маркеров; PDF с QR; Excel.
4. **Экран раунда** — шапка (турнир, клуб, поле, дата), «Экспорт PDF»,
   «Экспорт Excel», «Стартовый лист», вкладки **Счёт** и **Результаты**,
   информационная строка с ТИ и форматом игрока (например, «Стэйблфорд
   (игра на очки)»), фильтры по группам/полу/«Без группы», таблица лунок
   1–18 со строками «Длина / Пар / Индекс» и редактируемыми ударами.
5. **Результаты** — игрок, счёт, нетто, очки стэйблфорда; сортировка по
   клику на заголовок; призёры 1/2/3 подсвечены (в интерфейсе и в PDF);
   экспорт PDF/Excel; ручные правки счёта и очков.
6. **Карточка игрока** — ФИО, HI, CH, пар поля, таблица
   «Длина / Пар / Индекс / Фора / Удары / Очки гросс / Очки нетто»,
   экспорт в PDF, ручное редактирование HI, CH, форы и ударов.

### Импорт участников из Excel

Участников можно загрузить ещё при создании турнира (блок «Участники турнира
(Excel)» в форме) и позже на вкладке **Участники** → «Импорт Excel». Разбор
(`TnMgrCore.parseParticipants` / `parseWorkbook`) идёт по всем листам,
столбцам и ячейкам:

- читаются **все листы** книги (`TnMgrIO.readWorkbookFile`), а не только первый;
- строка заголовков ищется среди первых строк — над ней бывают название
  турнира, дата и прочие шапки; повтор шапки, «Итого» и строки из одних
  номеров пропускаются молча;
- колонки понимаются по заголовкам RU/EN: `ФИО`, `Фамилия`, `Имя`, `Отчество`,
  `Игрок`, `Гандикап`/`HI`/`ИГ`/`Handicap Index`, `CH`/`Игровой гандикап`,
  `Пол`, `ТИ`, `Группа`, `Клуб`; колонки «Фамилия» + «Имя» собираются в ФИО
  «Фамилия Имя Отчество»;
- чего нет в заголовках — доопределяется по содержимому: колонка имён и
  колонка чисел-гандикапов находятся в любом месте таблицы, включая файлы
  без заголовков;
- гандикап читается в любом написании: `12,4`, `+2,5` (плюсовой хранится
  отрицательным — как в АГР), `HI 8.2`, `ИГ: 14`, `13.8 (HI)`; пустой
  гандикап допустим — участник добавится без HI;
- предпросмотр показывает листы, распознанные колонки (A, B, C…) и
  пропущенные строки; кнопка «Добавить» переносит состав в турнир.

В форме создания импортированные участники ждут в списке и попадают в
`tournaments/<tid>/players` (+`registeredPlayers`) сразу после нажатия
«Добавить»; на вкладке «Участники» — после подтверждения предпросмотра.
Группа из файла подставляется, если группа с таким названием уже есть в
турнире, иначе участник распределяется по диапазону гандикапа.

## 2. Сущности (ТЗ §7)

Данные хранятся в существующем дереве `tournaments/<tid>` — публичные
страницы, live-счёт и правила Firebase продолжают работать.

| Сущность | Путь | Поля |
|---|---|---|
| Tournament | `tournaments/<tid>` | `name`, `date`/`startDate`, `startTime`, `formats[]`, `formatsDict`, `club`, `course`, `note`, `status` (`draft`→`upcoming`→`active`→`completed`), `source`, `createdBy`, `createdAt`, `updatedAt` |
| Round | `tournaments/<tid>/rounds/<rid>` | `id`, `date`, `startTime`, `club`, `course`, `name`, `sheetAt`, `groupRounds{index:gid}`, `groupRoundId`, `createdAt` |
| Group | `tournaments/<tid>/groups/<gid>` (дубль в `divisions/<gid>`) | `id`, `name`, `hcpFrom`, `hcpTo`, `gender`, `tee`, `format`, `members{}`, `createdAt` |
| Player (участник турнира) | `tournaments/<tid>/players/<pid>` | `id`, `fio`/`name`, `firstName`, `middleName`, `lastName`, `hi`, `ch`, `gender`, `tee`, `groupId`, `fores{}`, `source`, `uid`, `addedBy`, `createdAt` |
| TournamentPlayer (регистрация) | `tournaments/<tid>/registeredPlayers/<pid>` | `name`, `handicap`, `hi`, `ch`, `gender`, `tee`, `groupId`, `source`, `uid`, `status`, `addedAt` |
| StartingSheet | `tournaments/<tid>/sheets/<rid>` | `roundId`, `tournamentId`, `options{}`, `entries{}`, `markers{}`, `columns[]`, `qr{payload}`, `createdAt`, `updatedAt` |
| StartingSheetEntry | `.../sheets/<rid>/entries/<pid>` | `playerId`, `playerName`, `firstName`, `middleName`, `lastName`, `gender`, `hi`, `ch`, `tee`, `format`, `groupId`, `groupName`, `flight`, `position`, `order`, `startTime`, `markerPlayerId`, `markerName`, `qr`, `scoreUrl` |
| MarkerAssignment | `.../sheets/<rid>/markers/<pid>` | `playerId`, `groupId`, `groupName`, `flight`, `position`, `qr`, `targets{}`, `generatedAt`; в раунде группы — `rounds/<gid>/markerAssignments` + кольцо `players/<pid>/markedBy` |
| Score | `tournaments/<tid>/scores/<rid>/<pid>/<hole>`, страницы счёта `rounds/<gid>/players/<pid>/scores/<hole>` | 1–20 (проверяется правилами) |
| Result | `tournaments/<tid>/results/<rid>/<pid>` | `playerName`, `gross`, `net`, `points`, `place`, `holesPlayed`, `manual`, `updatedAt` |
| QRCode | `.../sheets/<rid>/entries/<pid>/qr` и `.../markers/<pid>/qr` | ссылка `setup-round.html?round=<gid>&as=<pid>` (группа) или `scorer.html?round=<gid>&player=<pid>` (одиночка) |

## 3. Стартовый лист и QR

- Лист собирается ядром `buildSheet()`: игроки сортируются по гандикапу,
  распределяются по группам (`groupSize`, по умолчанию 4), флайты A/B/C
  (`groupsPerFlight`), старты с интервалом (по умолчанию 8 минут от первого
  времени), маркеры назначаются по кольцу внутри группы.
- QR-код маркера ведёт на существующую страницу ввода счёта, то есть
  переиспользует live-счёт, публичные таблицы и offline-очередь (`js/pwa.js`).
- Раунды групп создаются в `rounds/<gid>` (`mode:'group'`, `tournamentId`,
  `tournamentRoundId`, `accessKey`, `createdBy`). `createdBy` — uid маркера,
  если он зарегистрирован в клубе (тогда маркер может вносить счёт партнёров
  по правилам `rounds/$rid/players/$pid`), иначе uid организатора.
- PDF листа: название турнира, дата, раунд, поле; флайты и группы с порядком
  и временем старта; по игроку — имя, ТИ, формат, группа, маркер; QR маркера
  рядом с группой; опционально QR турнира в шапке (галочка «QR турнира в
  шапке PDF»).

## 3.1 Старт турнира и статус раундов групп

Раунды групп создаются заранее, поэтому получают `status:'scheduled'` и
`scheduledStart` — момент старта турнира. Игрок, отсканировавший QR до
старта, видит на странице ввода счёта отсчёт («Турнир ещё не начался») и не
может вводить счёт: так задаёт гейт `isRoundGatedByStart()` (`js/utils.js`).

Раунд становится игровым (`status:'active'`) в один из трёх моментов:

1. **по времени** — `pestovoAutoStartRounds()` открывает все раунды, у которых
   наступил `scheduledStart` (вызывается на главной и в админке);
2. **принудительно** — кнопка «Старт» в карточке турнира
   (`TnMgrData.startTournament`) переводит турнир в `active` **и** открывает
   все его запланированные раунды, даже если плановое время ещё не наступило
   (старт перенесли, шотган, задержка из-за погоды);
3. **на открытой странице игрока** — когда отсчёт доходит до нуля
   (`openScheduledRound()` в `js/live.js`).

Правка или перегенерация стартового листа НЕ возвращает живой раунд в
`scheduled`: `materializeRound()` сохраняет прежний статус раунда, а для
уже начатого турнира создаёт раунд сразу активным. Иначе добавленный в лист
игрок снова получал бы «Турнир ещё не начался» на уже идущем турнире.

## 4. Синхронизация

Правки инлайна в стартовом листе синхронизируются с участниками
(`players/<pid>`, `registeredPlayers/<pid>`) и пересобирают карту маркеров;
правки в карточке игрока (HI/CH/фора/ТИ) и в таблице участников обновляют
лист. Удары, введённые на экране счёта, пишутся и в `rounds/<gid>` (страницы
ввода счёта), и в зеркало `tournaments/<tid>/scores/<rid>`; ручные правки
результатов сохраняются в `results/<rid>` и не затираются пересчётом
(`saveResults` без `force`).

## 5. Права

Раздел виден администраторам клуба (`users/<uid>/role === 'admin'`) и
мастер-сессии турнира (UID `tournament-master` с claim). Кнопка вкладки
скрывается для остальных (`TnMgr.syncTabVisibility`), данные пишутся в
существующие узлы, поэтому действующие правила `database.rules.json` не
менялись.

## 6. Печатные счётные карточки (вкладка «🎴 Счетные карточки»)

Конструктор печатных карточек турнира (`js/tn-mgr-printcards.js`, стили
обвязки — `css/tn-mgr-printcards.css`). Данные дизайна лежат одним узлом
`tournaments/<tid>/printScorecards` и применяются сразу ко **всем** карточкам;
состав карточек каждый раз пересобирается из живых данных турнира.

- **Актуальность.** Имена, HCP, ТИ, стартовые лунки, время и флайты берутся из
  участников и стартового листа при каждом открытии вкладки и при каждом
  изменении турнира (подписка Firebase). Ручные правки полей помечаются флагом
  `edits` и переживают обновление; кнопка «Пересобрать карточки» возвращает всё
  к данным турнира. Галочка «Подставлять текущий счёт раунда» переносит в
  карточку live-удары (`readRoundScores`).
- **Одна карточка-эталон.** На предпросмотре открыта и редактируется ровно одна
  карточка (клик по тексту — правка на месте), остальные лежат свёрнутыми
  неактивными строками; «Настроить» раскрывает другую. Дизайн (размер карточки,
  кегли, отступы, строки таблицы, оверлеи, подписи) общий, поэтому правка
  эталона синхронизируется со всеми карточками немедленно.
- **Предпросмотр листа.** Лист A4 landscape рисуется в настоящих миллиметрах и
  масштабируется под ширину вкладки (`fitStage()`), поэтому карточка всегда
  видна целиком; на узком экране по умолчанию показывается крупный режим
  «только карточка». Раскладка по умолчанию — крупная карточка 147×200 мм при
  масштабе 140% со смещением 90×40 мм (одна на лист); при таком масштабе на
  лист входит одна карточка — `cardsPerSheet()` сам уменьшает число карточек,
  чтобы вторая не уехала за край бумаги.
- **Вписывание в лист.** Если раскладка не помещается на A4 landscape,
  `pageFit()` считает коэффициент вписывания, и **предпросмотр с печатью
  совпадают**: карточка стоит там же и того же размера, что и на бумаге. Панель
  «Размеры» пишет фактический масштаб, кнопка «Вписать в лист» подбирает
  максимальный размер (до 105% для одной карточки) и центрует её. Раскладка
  организатора больше не сбрасывается: сохранённые смещения и масштаб живут.
- **Размеры всего.** Панель «Размеры и место на листе»: ширина/высота карточки,
  её место X/Y, зазор, масштаб печати, карточек на листе и все кегли/отступы/
  линии в миллиметрах (CSS-переменные `--tnpc-*`, один источник для экрана и
  печати — `cardCssText()`).
- **Лого, QR, текст.** Оверлеи перетаскиваются мышью и растягиваются за золотой
  уголок, их позиции и размеры правятся числами в панели «Лого и QR»; картинку
  можно перетащить файлом прямо на предпросмотр. QR по умолчанию ведёт на
  страницу ввода счёта игрока (как в стартовом листе), двойной клик — своя
  ссылка. Отключённые оверлеи не печатаются.
- **Подписи снизу.** «Игрок / Маркер / Судья» по умолчанию остаются только на
  экране (с пометкой «не печатается») и в печать/PDF не попадают; вернуть их в
  печать можно галочкой в панели «Состав информации», там же выбираются видимые
  блоки (клуб, дата, HCP, ТИ, лунка, время, флайт, строки таблицы, итоги).
- **Фора черточками.** Удары форы показаны наклонными черточками в правом
  верхнем углу клетки счёта: одна черточка за каждый удар на лунке (как на
  бланке клуба и на экранных карточках), минусовая фора — красным. У связки
  строка «Удары» своя у каждого игрока, и черточки соответствуют своему игроку.
  Тот же вид черточек использует печатная карточка раунда
  (`TnMgrCore.scorecardsHtml`).
- **Печать.** «Печать всех» / «Печать» / «PDF» открывают документ
  `A4 landscape` (ориентация выставляется автоматически, поля и колонтитулы не
  печатаются) с 1–2 карточками на лист; внешняя рамка карточки на бумагу не
  идёт. Если всплывающие окна заблокированы, документ печатается из скрытого
  iframe (`TnMgrIO.printInFrame`) — раньше в этом случае уходил пустой лист.
  Печать самой вкладки из админки (Ctrl+P) тоже альбомная и показывает только
  лист с карточкой. Строка состояния показывает, из каких данных собраны
  карточки (участники, раунд, стартовый лист).

Проверка геометрии в живом браузере (карточка видна целиком, правки мгновенны,
подписи не печатаются): `npm run check:printcards`
(`tools/check-printcards-preview.js` + `tools/harness/printcards.html`).
