# Менеджер турниров (вкладка «Турниры 🏆»)

Полный цикл работы организатора с турниром прямо в админ-панели: создание
турнира, раунды, группы, участники, стартовый лист с QR-кодами, счёт по
лункам, результаты и карточка игрока. Система переиспользует существующую
инфраструктуру клуба — публичный каталог `tournaments.html`, страницы
ввода счёта (`setup-round.html` / `scorer.html`) и общие правила Firebase.

```
admin.html → вкладка «Турниры 🏆» (#tab-tnmanager → #tnm-root)
  js/tn-mgr.js        точка входа TnMgr (open/boot, права доступа)
  js/tn-mgr-ui.js     маршрутизация, список, форма, карточка, модалки
  js/tn-mgr-sheet.js  вкладка «Стартовый лист»: генерация, QR, колонки, PDF
  js/tn-mgr-round.js  экран раунда (Счёт/Результаты) и карточка игрока
  js/tn-mgr-data.js   слой данных Firebase RTDB
  js/tn-mgr-io.js     печать PDF (окно печати), Excel (SheetJS/CSV), импорт
  js/tn-mgr-core.js   чистое ядро: форматы, поиск RU/EN, WHS, лист, результаты
```

## 1. Как пользоваться

1. **Турниры** — таблица «Название / Дата», кнопка «Создать турнир».
2. **Новый турнир** — название\*, дата начала\*, время старта\*, формат
   (мультивыбор из пополняемого справочника: 20 встроенных форматов + свои),
   клуб, поле, примечание. Кнопки «Добавить» / «Назад». Черновик формы
   автоматически сохраняется в `tnDrafts/<uid>` и в localStorage
   (`pestovo_tn_mgr_draft`).
3. **Карточка турнира** — «Назад», название + дата, «Изменить», кнопки
   жизненного цикла («Старт», «Пауза»/«Возобновить», «Принудительный финиш»,
   «Удалить») и вкладки:
   - **Раунды** — «Добавить», таблица с датой (правится на месте), «Удалить»,
     клик по строке открывает экран счёта.
   - **Группы** — «Добавить группу», таблица «Название / HCP», «Удалить»;
     форма группы: название\*, гандикап от/до, пол, ТИ, формат.
   - **Участники** («Гольфисты») — поиск с автодополнением по фамилии на
     русском и английском, ручное добавление, импорт Excel/CSV, вставка
     таблицы, справочник игроков клуба, счётчики «Всего / мужчин / женщин»,
     удаление, экспорт в PDF, «Гости и гандикапы» (регистрация участников в
     справочнике сайта и обмен гандикапами с админ-панелью — §4.1).
   - **Стартовый лист** — генерация из участников, групп, ТИ, формата и
     раундов; инлайн-правка любого поля; колонки настраиваются; QR-коды
     маркеров; PDF с QR; Excel; «Удалить всех» очищает лист раунда
     (состав турнира не трогает).

### Стартовый лист пачкой (вставка таблицы)

Кнопка «Вставить таблицу» во вкладке **Участники** принимает не только
список ФИО, но и готовый стартовый лист — время и состав флайта в одной
строке:

```
10:00: Неделько Александр, Свиридов Виктор, Гималетдинов Рустем
10:10: Петров Иван, Сидоров Олег
10:20 (лунка 10): Смирнова Анна, Козлова Мария
```

- время — `ЧЧ:ММ` (`:`, `.` или пробел: `9:5`, `09.05`, `9 05`);
- имена разделяются запятой, `;`, табуляцией или `|`;
- стартовая лунка — `(лунка 10)`, `л. 10`, `hole 10`, `#10`; по умолчанию 1;
- строка = флайт; одинаковое время и лунка объединяются в один флайт;
- ФИО приводится к виду «Фамилия Имя Отчество» (полностью строчные и
  полностью прописные имена исправляются, смешанный регистр не трогается);
- пол определяется по имени/отчеству;
- строка без времени не превращается в флайт — она попадает в
  предупреждения модалки.

Имена сверяются со справочником (`matchPlayerByName`: точное совпадение →
набор слов → транслит): найденные берутся с гандикапом и ТИ, ненайденные
добавляются как новые участники. Лист собирается из готовых флайтов
(`generateSheetFromFlights`), автоподбор по гандикапам не выполняется —
номера флайтов и время старта остаются ровно как во вставленном тексте.

### Удаление участников

Чекбоксы в таблице участников, «Выделить всё», «Удалить выбранных (N)» и
«Удалить всех» — с подтверждением. `removePlayers` снимает игрока со всех
связанных сущностей одним атомарным обновлением: `players`,
`registeredPlayers`, составы групп и дивизионов, записи и QR-привязки
стартовых листов, `scores`/`results` раундов, составы раундов групп.
После удаления игрок не попадает в автоподбор, лидерборд и печатные
карточки.
4. **Экран раунда** — шапка (турнир, клуб, поле, дата), «Экспорт PDF»,
   «Экспорт Excel», «Стартовый лист», вкладки **Счёт** и **Результаты**,
   информационная строка с ТИ и форматом игрока (например, «Стэйблфорд
   (игра на очки)»), фильтры по группам/полу/«Без группы», таблица лунок
   1–18 со строками «Длина / Пар / Индекс» и редактируемыми ударами.
5. **Результаты** — игрок, счёт, нетто, очки стэйблфорда; сортировка по
   клику на заголовок; призёры 1/2/3 подсвечены (в интерфейсе и в PDF);
   экспорт PDF/Excel; ручные правки счёта и очков.
6. **Карточка игрока** — ФИО, HI, CH, пар поля, таблица
   «Длина / Пар / Индекс / Фора / Удары / Очки гросс / Очки нетто»,
   экспорт в PDF, ручное редактирование HI, CH, форы и ударов.

### Импорт участников из Excel

Участников можно загрузить ещё при создании турнира (блок «Участники турнира
(Excel)» в форме) и позже на вкладке **Участники** → «Импорт Excel». Разбор
(`TnMgrCore.parseParticipants` / `parseWorkbook`) идёт по всем листам,
столбцам и ячейкам:

- читаются **все листы** книги (`TnMgrIO.readWorkbookFile`), а не только первый;
- строка заголовков ищется среди первых строк — над ней бывают название
  турнира, дата и прочие шапки; повтор шапки, «Итого» и строки из одних
  номеров пропускаются молча;
- колонки понимаются по заголовкам RU/EN: `ФИО`, `Фамилия`, `Имя`, `Отчество`,
  `Игрок`, `Гандикап`/`HI`/`ИГ`/`Handicap Index`, `CH`/`Игровой гандикап`,
  `Пол`, `ТИ`, `Группа`, `Клуб`; колонки «Фамилия» + «Имя» собираются в ФИО
  «Фамилия Имя Отчество»;
- чего нет в заголовках — доопределяется по содержимому: колонка имён и
  колонка чисел-гандикапов находятся в любом месте таблицы, включая файлы
  без заголовков;
- гандикап читается в любом написании: `12,4`, `+2,5` (плюсовой хранится
  отрицательным — как в АГР), `HI 8.2`, `ИГ: 14`, `13.8 (HI)`; пустой
  гандикап допустим — участник добавится без HI;
- предпросмотр показывает листы, распознанные колонки (A, B, C…) и
  пропущенные строки; кнопка «Добавить» переносит состав в турнир.

В форме создания импортированные участники ждут в списке и попадают в
`tournaments/<tid>/players` (+`registeredPlayers`) сразу после нажатия
«Добавить»; на вкладке «Участники» — после подтверждения предпросмотра.
Группа из файла подставляется, если группа с таким названием уже есть в
турнире, иначе участник распределяется по диапазону гандикапа.

## 3. Стартовый лист и QR

- Лист собирается ядром `buildSheet()`: игроки сортируются по гандикапу,
  распределяются по группам (`groupSize`, по умолчанию 4), флайты A/B/C
  (`groupsPerFlight`), старты с интервалом (по умолчанию 8 минут от первого
  времени), маркеры назначаются по кольцу внутри группы.
- **Во флайте минимум 3 игрока** (`MIN_START_GROUP`, `startGroupSizes()`):
  размеры групп выравниваются — 6 → 3+3, 7 → 4+3, 10 → 4+3+3, 11 → 4+4+3
  (раньше выходило 4+4+2+1). Маленькая зачётная группа, которую нельзя
  разбить на флайты по 3+ (1, 2 или 5 игроков при размере 4), объединяется
  при разбиении с соседней, но у каждого игрока остаётся своя зачётная группа
  (`groupId`/`groupName`). Если в листе всего 5 игроков — один флайт из 5;
  меньше 3 — один флайт из всех.
- **Публикация на сайте.** Лист из админки сам по себе на странице «Турниры»
  не виден. Над листом — панель «Опубликовать на сайте»: кнопка собирает из
  листа протокол `protocols/tnm_<tid>_<rid>` (`source:'tn-manager'`,
  стартовые группы со временем, лункой, флайтом, маркерами, точным и полевым
  HCP) и отметку `tournaments/<tid>/sheetPublish/<rid>`. На странице турнира
  (`tournaments.html?id=<tid>&tab=start`) появляется стартовый лист с QR каждой
  группы и кнопкой «Открыть лист для печати» (`qr-start.html?p=…`); у
  многодневного турнира — по блоку на раунд. Опубликованный лист обновляется
  автоматически при пересборке и правках (ТИ, маркер, игроки); «Снять с
  публикации», удаление листа, раунда или турнира убирают протокол.
- QR-код маркера ведёт на существующую страницу ввода счёта, то есть
  переиспользует live-счёт, публичные таблицы и offline-очередь (`js/pwa.js`).
- Раунды групп создаются в `rounds/<gid>` (`mode:'group'`, `tournamentId`,
  `tournamentRoundId`, `accessKey`, `createdBy`). `createdBy` — uid маркера,
  если он зарегистрирован в клубе (тогда маркер может вносить счёт партнёров
  по правилам `rounds/$rid/players/$pid`), иначе uid организатора.
- PDF листа: название турнира, дата, раунд, поле; флайты и группы с порядком
  и временем старта; по игроку — имя, ТИ, формат, группа, маркер; QR маркера
  рядом с группой; опционально QR турнира в шапке (галочка «QR турнира в
  шапке PDF»).

## 3.1 Старт турнира и статус раундов групп

Раунды групп создаются заранее, поэтому получают `status:'scheduled'` и
`scheduledStart` — момент старта турнира. Игрок, отсканировавший QR до
старта, видит на странице ввода счёта отсчёт («Турнир ещё не начался») и не
может вводить счёт: так задаёт гейт `isRoundGatedByStart()` (`js/utils.js`).

Раунд становится игровым (`status:'active'`) в один из трёх моментов:

1. **по времени** — `pestovoAutoStartRounds()` открывает все раунды, у которых
   наступил `scheduledStart` (вызывается на главной и в админке);
2. **принудительно** — кнопка «Старт» в карточке турнира
   (`TnMgrData.startTournament`) переводит турнир в `active` **и** открывает
   все его запланированные раунды, даже если плановое время ещё не наступило
   (старт перенесли, шотган, задержка из-за погоды);
3. **на открытой странице игрока** — когда отсчёт доходит до нуля
   (`openScheduledRound()` в `js/live.js`).

Правка или перегенерация стартового листа НЕ возвращает живой раунд в
`scheduled`: `materializeRound()` сохраняет прежний статус раунда, а для
уже начатого турнира создаёт раунд сразу активным. Иначе добавленный в лист
игрок снова получал бы «Турнир ещё не начался» на уже идущем турнире.

## 3.2 Пауза турнира (гроза, поломка, ожидание поля)

Кнопка **«⏸ Пауза»** появляется в карточке идущего турнира (`status:'active'`),
рядом с «Старт» и «Принудительный финиш». Организатор выбирает причину из
списка — гроза/непогода, перерыв/обед, остановка маршалом или судьёй, задержка
на поле, техническая пауза, другая причина — или пишет свою формулировку, а
`TnMgrData.pauseTournament(tid, reason, byName)`:

- помечает турнир: `paused:true`, `pausedAt`, `pauseReason`, `pausedBy`,
  `pausedByName` и добавляет запись в `pauseHistory[]`;
- останавливает **живые раунды групп** этого турнира (`rounds/<gid>`), у которых
  `tournamentId === tid` и статус не `completed`, — те же поля паузы плюс
  `pausedByTournament:<tid>`, чтобы возобновление сняло только свою паузу;
- раунды, уже поставленные на паузу вручную (маршалом на странице раунда),
  не перепомечаются: у них нет `pausedByTournament`, и «Возобновить» их не тронет.

**«▶ Возобновить»** (`resumeTournament`) снимает паузу с турнира и с его
раундов, закрывает запись `pauseHistory` (`resumedAt`) и копит
`totalPausedMs` — суммарное время простоя, которое темп игры и судейские
отчёты показывают как задержку.

Пауза турнира **не блокирует ввод счёта** — ровно как пауза раунда: маркер,
который уже доиграл лунку, может её записать. Меняются только статус и
отображение: на публичных страницах турнир получает бейдж «⏸ На паузе»
(`js/tournaments.js`, `js/tournament-public.js`), в карточке турнира — баннер
с причиной и временем, кнопка «Старт» на паузе недоступна. `status` и
`lifecycleStatus` при этом не меняются: пауза — отдельный флаг, поэтому
снятие паузы возвращает турнир в прежнее состояние, а не «заново стартует».

## 4. Синхронизация

Правки инлайна в стартовом листе синхронизируются с участниками
(`players/<pid>`, `registeredPlayers/<pid>`) и пересобирают карту маркеров;
правки в карточке игрока (HI/CH/фора/ТИ) и в таблице участников обновляют
лист. Удары, введённые на экране счёта, пишутся и в `rounds/<gid>` (страницы
ввода счёта), и в зеркало `tournaments/<tid>/scores/<rid>`; ручные правки
результатов сохраняются в `results/<rid>` и не затираются пересчётом
(`saveResults` без `force`).

## 4.1 Гости и справочник сайта (гандикапы из админ-панели)

Участники турнира живут в `tournaments/<tid>/players`, а все списки сайта —
«Игроки и роли» в админке, выбор игрока в live-скоринге, рейтинги, импорт
Excel, синхронизация с АГР — читают справочник `users/` и его публичное
зеркало `usersPublic/`. Поэтому состав турнира регистрируется в справочнике:

- **автоматически** — после добавления участников (вручную, вставкой таблицы
  или импортом Excel) вызывается `TnMgrData.syncPlayersToDirectory()`;
- **кнопкой «Гости и гандикапы»** на вкладке «Участники» — окно «Справочник
  игроков и гандикапы» показывает, сколько участников уже связано со
  справочником, и предлагает три действия (ниже).

Игрок ищется в справочнике `findDirectoryUid()`: сначала по явному `uid`,
затем по ФИО — точное совпадение нормализованного имени или «сильное»
совпадение `isSamePersonByFio()` (порядок «Фамилия Имя Отчество» и «Имя
Отчество Фамилия» — один человек; однофамильцы остаются разными людьми).
Удалённые профили (`deleted`, `isPlayerDeleted`) не подбираются.

Найденный профиль **не перезаписывается**: дополняются только пустые поля,
гандикап — по режиму (см. таблицу), отметка АГР `hcpSource:'rusgolf'` не
перебивается. Если игрока в справочнике нет, создаётся **гость** — та же
запись, которую делает live-скоринг (`isGuest:true`, `role:'player'`, id
`guest_<имя>` через `buildGuestUserId()`), и сразу в двух узлах: `users/<uid>`
**и** `usersPublic/<uid>`, иначе гость не появится ни в списках выбора, ни на
публичных страницах. Связь закрепляется в турнире: `players/<pid>/uid`,
`players/<pid>/directorySyncedAt` и `registeredPlayers/<pid>/uid` (его читает
публичная страница турнира). Повторная синхронизация дублей не создаёт, а в
таблице участников связанные игроки помечены (`.tnm-dir-linked`).

| Кнопка окна | Что делает |
|---|---|
| **Зарегистрировать гостей на сайте** | `syncPlayersToDirectory(tid, players, {handicaps:'fill'})` — создаёт недостающих гостей; гандикап участника переносится в профиль, только если там пусто |
| **Гандикапы турнира → сайт** | `pushHandicapsToDirectory()` — HI участника перезаписывает `users/<uid>.handicap` и зеркало, ставит `hcpUpdatedAt` и `hcpSource:'tournament'` |
| **Гандикапы сайта → турнир** | `pullHandicapsFromDirectory()` — HI из профиля (после правки в админке, импорта Excel или АГР) уходит в `players/<pid>.hi`, `registeredPlayers/<pid>` и во все стартовые листы `sheets/<rid>/entries/<pid>`, CH пересчитывается |

**CH (игровой гандикап) пересчитывается только автоматический.** Если
сохранённый CH совпадает с расчётом от прежнего HI (или пустой) — считаем
заново; если организатор выставил CH вручную (другие ти, скидка) — он не
затирается. Обратная сторона та же: правка гандикапа в админ-панели
(`js/admin-players.js` — карточка игрока, `js/admin-players-excel.js` —
импорт, `js/admin-agr.js` — раскатка АГР) вызывает
`pestovoSyncHcpToTournaments()` из `js/utils.js`, которая находит участника по
`uid` во всех **незавершённых** турнирах и обновляет `players/<pid>.hi`,
`registeredPlayers/<pid>` и записи стартового листа. Гандикап, приехавший из
АГР, остаётся первоисточником: `hcpSource` не понижается до `tournament`.

## 5. Права

Раздел виден администраторам клуба (`users/<uid>/role === 'admin'`) и
мастер-сессии турнира (UID `tournament-master` с claim). Кнопка вкладки
скрывается для остальных (`TnMgr.syncTabVisibility`), данные пишутся в
существующие узлы, поэтому действующие правила `database.rules.json` не
менялись.

## 6. Печатные счётные карточки (вкладка «🎴 Счетные карточки»)

Конструктор печатных карточек турнира (`js/tn-mgr-printcards.js`, стили
обвязки — `css/tn-mgr-printcards.css`). Данные дизайна лежат одним узлом
`tournaments/<tid>/printScorecards` и применяются сразу ко **всем** карточкам;
состав карточек каждый раз пересобирается из живых данных турнира.

- **Актуальность.** Имена, HCP, ТИ, стартовые лунки, время и флайты берутся из
  участников и стартового листа при каждом открытии вкладки и при каждом
  изменении турнира (подписка Firebase). Ручные правки полей помечаются флагом
  `edits` и переживают обновление; кнопка «Пересобрать карточки» возвращает всё
  к данным турнира. Галочка «Подставлять текущий счёт раунда» переносит в
  карточку live-удары (`readRoundScores`).
- **Одна карточка-эталон.** На предпросмотре открыта и редактируется ровно одна
  карточка (клик по тексту — правка на месте), остальные лежат свёрнутыми
  неактивными строками; «Настроить» раскрывает другую. Дизайн (размер карточки,
  кегли, отступы, строки таблицы, оверлеи, подписи) общий, поэтому правка
  эталона синхронизируется со всеми карточками немедленно.
- **Предпросмотр листа.** Лист A4 landscape рисуется в настоящих миллиметрах и
  масштабируется под ширину вкладки (`fitStage()`), поэтому карточка всегда
  видна целиком; на узком экране по умолчанию показывается крупный режим
  «только карточка». Раскладка по умолчанию — крупная карточка 147×200 мм при
  масштабе 140% со смещением 90×40 мм (одна на лист); при таком масштабе на
  лист входит одна карточка — `cardsPerSheet()` сам уменьшает число карточек,
  чтобы вторая не уехала за край бумаги.
- **Вписывание в лист.** Если раскладка не помещается на A4 landscape,
  `pageFit()` считает коэффициент вписывания, и **предпросмотр с печатью
  совпадают**: карточка стоит там же и того же размера, что и на бумаге. Панель
  «Размеры» пишет фактический масштаб, кнопка «Вписать в лист» подбирает
  максимальный размер (до 105% для одной карточки) и центрует её. Раскладка
  организатора больше не сбрасывается: сохранённые смещения и масштаб живут.
- **Размеры всего.** Панель «Размеры и место на листе»: ширина/высота карточки,
  её место X/Y, зазор, масштаб печати, карточек на листе и все кегли/отступы/
  линии в миллиметрах (CSS-переменные `--tnpc-*`, один источник для экрана и
  печати — `cardCssText()`).
- **Блоки таблицы растягиваются.** Каждая строка таблицы — № лунки, Пар,
  Длина, Индекс, Фора, Удары — самостоятельный блок со своими кеглем, высотой
  и шириной колонки подписи (пока поле не заполнено, значение наследуется от
  общих размеров). Блок тянут мышью прямо на карточке за три золотые ручки:
  ↕ — высота строк, ↔ — колонка подписи, ↘ — весь блок разом (кегль, высота и
  подпись растут пропорционально). Двойной клик по блоку открывает его
  настройки в панели «Цвет и шрифт». Свои размеры блока хранятся в
  `printScorecards/rows/<block>` и переживают перезагрузку; кнопка «Как у всех»
  возвращает наследование.
- **Длина лунок.** Новая строка «Длина, м» (после «Пар», до «Индекса»):
  включается/выключается галочкой в «Составе информации», значения берутся из
  справочника поля (`HOLES`/`defaultCourse().dist`, по умолчанию белые ТИ) и
  правятся прямо в клетках карточки или числами в панели «Лунки, пар, длина,
  индекс». Кнопки «Заполнить по ТИ» (Белые/Синие/Чёрные/Красные) заполняют
  все 18 длин из справочника; итоги OUT/IN/TOTAL считают только заполненные
  клетки, 0 = пустая клетка. У турниров, сохранённых до появления строки,
  «Длина» появляется автоматически на своём месте — порядок остальных строк
  не меняется (`normalizeRowOrder` вставляет новые строки канонически).
- **Цвет и шрифт.** Панель «Цвет и шрифт»: шрифт всей карточки (Arial по
  умолчанию + 8 вариантов), цвет текста, фон карточки, цвет линий и фон
  колонок OUT/IN/TOTAL — всё живьём, без перерисовки вкладки. Ниже — настройки
  каждого блока таблицы: свой кегль/высота/подпись, цвет текста, фон, шрифт и
  полужирный (клетки, подпись и черточки форы красятся вместе). Цвета
  хранятся hex-значениями и валидируются при загрузке; шрифт допускается
  только из списка (`safeFont`), поэтому сохранённые данные не ломают разметку.
- **Блоки целиком.** Таблица (№ лунки, Пар, Длина, Индекс, Фора, Удары) и
  шапка (турнир, клуб, дата, имя, HCP, ТИ, старт) двигаются и масштабируются
  как один блок. Синие ручки на карточке: ✥ — перенести блок в любое место
  карточки, ↔ — ширина, ↕ — размер всего содержимого (кегли, высоты строк,
  колонки подписей и итогов — пропорционально), ↘ — ширина и размер сразу.
  Первое перемещение «освобождает» блок из потока ровно там, где он стоял;
  те же значения (X/Y/ширина/размер %, галочка «свободное место», «Сбросить»)
  есть в панели «Размеры». Хранится в `printScorecards/boxes/{table,head}`
  (`free`, `xMm`, `yMm`, `wMm`, `k`); без настроек карточка выглядит как раньше.
- **Свои блоки.** Кнопки «+ Свой блок», «+ Маркер», «+ Подпись маркера»,
  «+ Гандикапы» в панели «Лого, QR, текст и свои блоки» добавляют оверлей
  `type:'block'`: шаблон текста (можно несколько строк) с подстановками
  `{player} {lastName} {firstName} {marker} {markerLast} {markerFirst} {hcp}
  {fieldHcp} {tee} {hole} {time} {flight} {group} {tournament} {date} {club}`
  — значения берутся для каждой карточки (маркер — тот, кто ведёт счёт игрока
  по стартовому листу). Блок перетаскивается и растягивается мышью, у него
  есть название, кегль, выравнивание, рамка (нет / вокруг / линия снизу для
  подписи), цвет текста, фон и полужирный; двойной клик по блоку открывает его
  настройки, чипы подстановок вставляют поле в позицию курсора.
- **Точный и полевой HCP.** В шапке карточки — «Точный HCP 12.4 · Полевой HCP
  14» (полевой — по ТИ и полу, как в стартовом листе; правится на месте,
  очистка возвращает расчёт). Полевой можно скрыть галочкой «Полевой HCP».
  Экранная карточка игрока (`js/tn-scorecard.js`) тоже всегда показывает оба.
- **Лого, QR, текст.** Оверлеи — лого, QR и **добавленный свой текст** —
  перетаскиваются мышью и растягиваются за золотой уголок, их позиции и
  размеры правятся числами в панели «Лого и QR»; картинку можно перетащить
  файлом прямо на предпросмотр. QR по умолчанию ведёт на страницу ввода счёта
  игрока (как в стартовом листе), двойной клик — своя ссылка. Отключённые
  оверлеи не печатаются.
- **Карточка двигается по листу.** В режиме «лист A4» у карточки есть ручка ✥
  в левом верхнем углу: её можно перетащить мышью (или пальцем) в любое место
  листа — координаты X/Y и масштаб тут же попадают в панель «Размеры» и в
  сохранённый дизайн, поэтому экран и бумага не расходятся. Ручка живёт только
  на экране (`data-tnpc-card-move`), в печать и PDF она не попадает, а в режиме
  «только карточка» её нет вовсе (двигать не по чему). Мелкое движение мыши
  (порог `DRAG_THRESHOLD_PX`) по-прежнему считается кликом: правка текста
  карточки и перетаскивание не мешают друг другу.
- **Подписи снизу.** «Игрок / Маркер / Судья» по умолчанию остаются только на
  экране (с пометкой «не печатается») и в печать/PDF не попадают; вернуть их в
  печать можно галочкой в панели «Состав информации», там же выбираются видимые
  блоки (клуб, дата, HCP, ТИ, лунка, время, флайт, строки таблицы — включая
  «Длину», — итоги).
- **Фора черточками.** Удары форы показаны наклонными черточками в правом
  верхнем углу клетки счёта: одна черточка за каждый удар на лунке (как на
  бланке клуба и на экранных карточках), минусовая фора — красным. У связки
  строка «Удары» своя у каждого игрока, и черточки соответствуют своему игроку.
  Черточки рисуются **всегда, когда у игрока есть фора**: если удары по лункам
  не выбраны/не введены вручную (`fores{}`), они считаются от игрового
  гандикапа и индекса сложности лунки (`handicapStrokesOnHole()`), а снятая
  галочка «Фора» в панели «Состав информации» убирает только отдельную строку
  «Фора» — сами черточки в клетках счёта остаются. Раньше вместе со строкой
  пропадал и удар форы, и карточка печаталась без черточек. Тот же вид черточек
  использует печатная карточка раунда (`TnMgrCore.scorecardsHtml`).
- **Печать.** «Печать всех» / «Печать» / «PDF» открывают документ
  `A4 landscape` (ориентация выставляется автоматически, поля и колонтитулы не
  печатаются) с 1–2 карточками на лист; внешняя рамка карточки на бумагу не
  идёт. Если всплывающие окна заблокированы, документ печатается из скрытого
  iframe (`TnMgrIO.printInFrame`) — раньше в этом случае уходил пустой лист.
  Печать самой вкладки из админки (Ctrl+P) тоже альбомная и показывает только
  лист с карточкой. Строка состояния показывает, из каких данных собраны
  карточки (участники, раунд, стартовый лист).

Проверка геометрии в живом браузере (карточка видна целиком, правки мгновенны,
подписи не печатаются): `npm run check:printcards`
(`tools/check-printcards-preview.js` + `tools/harness/printcards.html`).
