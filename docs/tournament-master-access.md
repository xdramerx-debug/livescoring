# Доступ к турнирам по мастер-паролю

Мастер-пароль **не** даёт права RTDB через `sessionStorage`. Админка проверяет его через Cloud Function `tournamentMasterSignIn` и входит в Firebase Auth через custom token с ограниченными правами. Привязывать личный аккаунт Firebase не нужно. Права на турниры, связанные турнирные раунды, протоколы и шаблоны задаются `database.rules.json`, ограничены 8 часами и не разрешают повышать собственную роль в `users`.

## Настройка перед публикацией

1. Выберите **новый длинный случайный** пароль. Старый временный пароль, который находился в браузерном коде, нельзя использовать: его знают все посетители старой версии сайта.
2. Вычислите SHA-256 UTF-8 пароля **локально**, не помещайте сам пароль в репозиторий или публичный `/settings` RTDB. Например, в bash: `read -rsp 'Новый пароль: ' p; echo; printf '%s' "$p" | sha256sum | cut -d' ' -f1; unset p` (ввод скрыт; используйте локальную защищённую среду).
3. Сохраните полученный хэш в Firebase Secret Manager под именем `TOURNAMENT_MASTER_PASSWORD_HASH` (`firebase functions:secrets:set TOURNAMENT_MASTER_PASSWORD_HASH --project livescore-b77e4`). Не записывайте его в клиентские настройки. Даже хэш короткого пароля поддаётся перебору; выбирайте сильный пароль.
4. Разверните **функцию, правила БД и hosting вместе**: `firebase deploy --only functions:tournamentMasterSignIn,database,hosting --project livescore-b77e4`. Для Cloud Functions и Secret Manager необходим настроенный проект Firebase с соответствующим тарифом/правами.
5. Удалите старые `/settings/adminAccess/masterPassword{,Hash}` и `/settings/admin/masterPassword{,Hash}` (они были публичными). При смене пароля обновите секрет и повторно разверните функцию; уже открытые сессии действуют до 8 часов или до выхода из админки.

Без настроенного серверного секрета вход по мастер-паролю **не сработает** (система намеренно не допускает небезопасный клиентский обход). После входа редактирование турнира, составов, заявок, статуса, протокола и его раундов работает напрямую по серверным правилам. Глобальные настройки клуба (например, общее поле и аккаунты пользователей) требуют обычных прав администратора Firebase.
